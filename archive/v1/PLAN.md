# План разработки sol-chef (архив V1)

> **V1 выполнен:** статический сайт, JSON, GitHub Pages.  
> **2.0:** папка [`v2/`](v2/) — план [v2/docs/PLAN.md](v2/docs/PLAN.md). Запреты ниже («без React, без БД, без VPS») к 2.0 не относятся.

Личный кулинарный справочник для себя, друзей и семьи. Статический сайт на GitHub Pages, все данные постепенно переезжают в JSON, наполнение через ИИ в Cursor.

**Домен (позже):** `sol-chef.ru`  
**Язык:** только русский  
**Ожидаемый объём:** ~50 рецептов, справочники по крупам и мясу, советы Энди Кукса

---

## Цели

- Удобно добавлять рецепты и советы через ИИ (без ручного копирования в файл).
- Делиться прямой ссылкой на рецепт или раздел с близкими.
- Максимально дёшево: бесплатный хостинг (GitHub Pages) + домен ~500–1500 ₽/год.
- CI не даёт сломать сайт битым JSON при push.

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Формат данных | Со временем весь контент в JSON |
| Страницы рецептов | Одна шаблонная `recipe.html?id=...`, не 50 отдельных HTML |
| Поиск и фильтры | Да, с первого дня на вкладке «Рецепты» |
| Аудитория | Личный сайт, без тяжёлого SEO |
| Наполнение | Через ИИ в Cursor (редактирует JSON напрямую) |
| Валидация | GitHub Actions при каждом push |
| Устаревшие файлы | `krupy_i_myaso.html` удалён |

## Что не делаем

- WordPress, CMS, база данных, VPS.
- React/Vue и сборщики (Vite, Webpack) — лишняя сложность.
- Отдельный HTML на каждый рецепт.
- Notion/API как бэкенд.

## Схема рецепта

Обязательные поля: `id`, `title`, `source_url`, `summary`, `tags`.

```json
{
  "id": "brizket-mangal",
  "title": "Брискет на мангале",
  "source_type": "video",
  "source_url": "https://youtube.com/...",
  "source_name": "Название канала",
  "tags": ["говядина", "мангал", "долгое"],
  "category": "говядина",
  "summary": "Краткий конспект в 2–4 предложения — видно в карточке.",
  "ingredients": ["брискет 2 кг", "соль крупная", "чёрный перец"],
  "steps": [
    "Натереть солью за сутки, убрать в холодильник.",
    "Непрямой жар 6–8 ч до 93°C внутри.",
    "Финальный прямой жар 2 мин для корки."
  ],
  "notes": "Отдых 30 мин под фольгой обязателен.",
  "added": "2026-07-17"
}
```

`source_type`: `"video"` или `"article"`.  
`id`: латиница через дефис, уникальный в массиве.

## Workflow: добавление через ИИ

### Основной способ (рекомендуется)

1. Открыть проект в Cursor.
2. В чат:

```
Добавь рецепт из этого видео: [ссылка]
Следуй data/schemas/recipe.schema.json и docs/ADD_RECIPE.md.
Файл: data/recipes.json
```

3. ИИ дописывает запись, проверяет уникальность `id`.
4. `git push` — сайт обновляется за 1–2 минуты.

### Запасной способ (только GitHub в браузере)

Edit `data/recipes.json` → вставить объект в массив → Commit.  
Риск опечаток в JSON; CI (этап 5) ловит ошибки до публикации.

## Как работать с планом в Cursor

1. Открыть только файлы текущего этапа.
2. Вставить промпт из раздела этапа (или: «Реализуй Этап N из PLAN.md»).
3. После этапа — отметить чеклисты `[x]` в этом файле.
4. Проверить локально (`npx serve`) и на GitHub Pages.
5. Новый этап — новый чат (или явное «переходим к Этапу N»).

## Подключение домена sol-chef.ru (когда купите)

1. Создать файл `CNAME` в корне репозитория с содержимым: `sol-chef.ru`
2. В DNS у регистратора:
   - A-записи на IP GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - или CNAME `www` → `ваш-логин.github.io` (если используете www)
3. В GitHub: Settings → Pages → Custom domain → `sol-chef.ru`
4. Дождаться HTTPS (обычно до 24 ч)

Документация: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site
