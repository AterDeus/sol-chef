## Главный редакционный критерий

> Минимальное количество воскресной работы, которое создаёт максимальное количество разных быстрых будничных блюд.

Слой — **component meal prep** (заготовка-основа → разные будничные блюда), не batch cooking (несколько больших кастрюль → разогрев той же еды).

Не оптимизировать «использовать всё купленное». Не заполнять 14 ячеек чистыми гарнирами. Один белок может быть основным и не должен визуально доминировать неделю. Альтернативы слота — страховка, не второй каталог. Новый slug автоматически не добавлять.

## 1. Задача человека (закрыто)

- 2 готовых набора.
- 7 дней, обед и ужин (14 слотов), без завтраков и десертов.
- База на 2 едока, количества считаются на эту базу (масштаб — приложение потом).
- Полуфабрикаты заранее: нарезка и **полуготовность** — это заготовка, не блюдо на стол.
- У каждого блюда набора **два тела шагов** (вариант B): в книге — с нуля; из набора — из контейнеров. **Не** «скрыли первые N шагов»: протокол вс может не совпасть с началом рецепта (другая нарезка, другая готовность, другой порядок, маринад в вс vs в будни). Каждый slug проверить отдельно. Большая часть совпадёт — это факт после сверки, не допущение.
- Большую порцию на **2 дня** можно, если на следующий день **вкусно** и безопасно. Второй слот — разогрев, не вторая полная готовка. Какие блюда так живут — решить по каждому, не списком типов.
- Сбор калькулятором не делать. Граф компонентов всё равно описать: какие контейнеры есть и какие slug их едят. Это задел и проверка, что набор не из 14 несвязанных корзин.

## 3. Тема набора

Следующий набор не стартовать с «что стыкуется в каталоге». Сначала сезон и питательный каркас по DESIGN. Каталог отвечает на вопрос «какими slug закрыть роли», а не «какую неделю можно выжать из курицы».

Рамки:

- Сильное пересечение сырья внутри набора (несколько белков + набор овощей/круп), иначе вс неподъёмен. Пересечение — следствие рациона, не цель «свести к одному белку».
- Разнообразие на 7 дней: не курица-лук 14 раз. Обед и ужин одного дня — разная роль (суп/крупа vs основное), не два одинаковых сковороды. Чистый гарнир не слот.
- Посуда будней — бытовая (сковорода, кастрюля, микроволновка для разогрева). Не требовать мангал каждый вечер.
- Не тащить десерты, завтраки, `sauce`/`preserve` как слот обеда/ужина (компонентом — можно: масло, жареный лук, говядина на волокна).
- Не плодить новые id, пока дыру нельзя закрыть существующим slug. Дыра → строка в ANALYSIS «не хватает такого-то блюда», не тихий новый рецепт.
- High-risk (сырая рыба, дикие грибы) в пилот не класть.

Гипотезы эксперимента №0 (не копировать как шаблон следующего набора):

1. Птица + овощи + крупа/суп, будни в основном сковорода — сильное ядро component meal prep, слабые слоты-гарниры и перекос белка.
2. Тушение (говядина или свинина) + супы/гарниры — batch cooking, длинное вс, малая экономия актив.

Оба набора не должны требовать одну и ту же морозилку на 20 контейнеров без нужды: часть ближних дней — холодильник, дальние — морозилка. Расписать по компоненту.

## 4. Слоты и «второй день»

14 слотов: `day` 1…7, `meal` `lunch` | `dinner`. День 1 = первый после вс (условно пн).

| `mode` | Смысл |
|--------|--------|
| `assemble` | Полуфабрикат **уже готов к употреблению**. Человек только соединяет / нарезает / собирает. Нет обязательной термической обработки. Пример: лаваш с готовой птицей, салат. Не «достал бульон, довёл, сварил лапшу». |
| `finish` | Нужна **термическая обработка**: довести до целевой SAFETY, сварить лапшу/крупу, прогреть полуфабрикат. Суп с лапшой из вс-бульона — `finish`. Вс-гуляш, который в будни греют на сковороде до 71 °C — `finish`, если прогрев значимая часть работы. |
| `reheat` | Только разогрев **готового результата слота вчерашнего дня** (`source.day + 1`). Тот же slug. Не первый показ воскресного контейнера. Не «через два дня» и не «в следующее воскресенье». |
| `from_prep` | Не писать. |

`reheat` только если `leftover_next_day.ok === true` **и** слот-источник — **вчера** (`day + 1`). Кляр, стейк, салат-листья, глазунья — скорее нет; гуляш, борщ, гречка, тушёная капуста — скорее да **на следующий день**; паста, жареная картошка, борщ через 4 дня, борщ с картофелем из морозилки — нет.

Большая порция: `servings_cooked` на слоте-источнике (напр. 4 при базе 2) и `feeds_slots` (включая источник). Два слота = вчерашний приём + сегодняшний, не «среда и воскресенье».

Каждый слот имеет **`source`** (откуда еда, без контейнеров внутри) и при `assemble`/`finish` — **`container_ids`** на самом слоте:

- `source`: только `{ "kind": "weekend" }` или `{ "kind": "slot", "day": 1, "meal": "lunch" }`;
- `assemble` / `finish` → `kind=weekend` + непустые `container_ids` того же kit;
- `reheat` → `kind=slot` на слот **вчерашнего дня** того же kit (`source.day + 1 === этот day`); `container_ids` нет / `[]`.

Слот — законченная тарелка: [MEAL-CONTRACT.md](../weekly/MEAL-CONTRACT.md). Второй FK рецепта нет. Сопровождение — в `steps` и в необязательном `companions[]` (ярлык, `kind`, при нужде `container_ids`). Редакционно слот имеет `MEAL_TYPE` (`single` / `main_plus_companion` / `soup_plus_companion` / `bowl`); поле в JSON **пока не обязано**. Не плодить в книге `borshch-s-grenkami`.

```json
"companions": [
  { "kind": "bread", "label": "Бородинский, натереть чесноком" },
  { "kind": "dairy_flavor", "label": "Сметана в тарелку" },
  { "kind": "fresh_veg", "label": "Огурец кружками" }
]
```

Нет поля `from`. Нет `side_recipe`. Нет `container_ids` внутри `source`.

`flavor` — короткий вкус.  
`alternatives`: 0–3 объекта по контракту JSON; редакционно для первого релиза **0–2**, страховка, не конструктор вечера. Не голые slug:

```json
{ "slug": "…", "label": "Лаваш с курицей", "mode": "assemble", "container_ids": ["c2", "c5"] }
```

Не требуют новых компонентов, закупки, вс. `container_ids` — боксы **этого kit**; slug — published `Recipe`. Пусто — `[]`. Валидность проверяет импорт, не фронт.

`no_leftover` у каждого `reheat` — чем слот становится при галочке «Без вчерашнего» (до закупки): **дополнительное** блюдо каталога, которого нет в 14 ячейках набора, не перестановка уже стоящего слота и не дыра. Боксы kit и/или `shopping_add`. У источника leftover — `no_leftover.steps` без «остаток на завтра». Не солвер. Контракт поля — [DATA-MODEL.md](../DATA-MODEL.md).

Ворота: одинаковое блюдо два слота подряд — нет, кроме пары готовка + `reheat` следующего дня. Рыба/морепродукты/баранина — не два календарных **дня** подряд (`protein_primary`, не щепотка). Птица/говядина/свинина — не дольше двух дней подряд. Два рыбных слота в один день — один рыбный день и два приёма квоты; без специальной причины так не проектировать.

Не 14 уникальных slug ценой разрыва сырья. Лучше 8–12 семейств + `reheat`.

## 5. Разбор каждого slug (обязателен)

Для каждого slug в слоте `assemble`/`finish`. Для `reheat` — как разогреть и до какой °C, ссылка на слот-источник.

Читать фактические `steps`, `ingredients`, `prep`, `notes`, температуры.

Ответить:

1. Что в вс, чтобы будни были 10–20 мин?
2. Совпадает ли с первыми шагами книги? Если нет — что другое.
3. Править тело с нуля в книге или только второе тело?
4. `steps_from_prep` — полное будничное тело, не «шаги 4–7».
5. Какие `component_id` и `qty`+`unit` на базу слота.
6. `leftover_next_day` для готового **блюда** (не компонента): можно ли слот `reheat`.

Нельзя: вычеркнуть «нарезать лук», если в вс лук уже пассерован.

## 6. Компоненты, контейнеры, шкала вс

Порядок: компоненты → нарезка по контейнерам → слоты с `source`.

**Источник истины связей — слот.`source`.**  
`component.eaten_by` и `container.eaten_by_slots` **не писать**. Кто ест компонент — производное: слоты `weekend`, чьи контейнеры с этим `component_id`, плюс каскад `reheat` от этих слотов.

Компонент **не** 1:1 с контейнером. 1400 г курицы → №1…№4. У компонента явные `container_ids`. Сумма `qty` контейнеров = `qty` компонента (тот же `unit`).

Количества везде **`qty` + `unit`** (`g` `ml` `pcs` `bunch` … как VOCAB). Не `qty_g`.

У компонента: id, title, canonical_ids, qty/unit, `container_ids`, `weekend_steps` (как делать: промыть, нарезать — **не** расписание), parcook, storage (срок, слой, не путать с номером бокса).

У контейнера: id, label (`№2 бульон` — что внутри, не день недели), `component_id`, qty/unit, `place` fridge|freezer|pantry, `thaw_before_day`. Какие слоты его едят — из `source.container_ids`, не копировать сюда. День, когда доставать из мороза, живёт в `thaw_before_day`, не в `label`. Закрытая магазинная банка — `place: pantry`, не контейнер холодильника.

`storage.fridge_days` — по [WEEKLY-PREP-DESIGN.md](../weekly/WEEKLY-PREP-DESIGN.md) §29: готовое по умолчанию **3**, не 6. Пометка «не ГОСТ» не разрешает смелый срок.

**`weekend_timeline`** — единственный протокол вс для приложения: что и когда (параллель §6.1). Охлаждение большого объёма — отдельная точка шкалы, не ремарка. «Сразу в морозилку» с горячим бульоном/мясом — стоп.  
**`weekend_protocol` не писать.** Как делать шаг — `weekend_steps` компонента; когда — шкала. UI вс = cook mode по шкале, не второй список.

Минуты только в `metrics` (целые минуты). Нет `weekend_active_hours_estimated`.  
`t_sunday_active_min` — сумма интервалов шкалы, где руки заняты, **включая** нарезку, лепку, мойку доски, раскладку по боксам и сбор водяной бани. Лучше завысить, чем занизить.  
`t_sunday_wall_min` — `t_min` последней точки (стена).  
`t_weekdays_active_min` / `t_scratch_active_min` — карта §6. Подпись человеку: «эта же неделя с нуля», не «обычная готовка 8 часов». Нет числа у slug — `null`.

### 6.1. Параллель вс — один прогон агента

Солвер — задача анализа, **один раз на набор**. Не Django, не калькулятор, не повтор на `/prep`.

Ресурсы (пока человек не сказал иначе): одни руки; одна духовка (один режим); две конфорки. Остывание мяса/птицы и большого горячего объёма — обязательный `passive` на `counter` или водяная баня, затем холод; в морозилку не с плиты (SAFETY).

Сначала длинный `passive` (крупа, духовка). Пока ждут — резать и фасовать. Руки не две работы в одну минуту. Два режима духовки сразу — нельзя.

Выход — `weekend_timeline[]`. В ANALYSIS: что параллельно, простой рук, конфликт духовки. Последовательная шкала при наличии варки/духовки/остывания — переделать.

Человек может сдвинуть точку в JSON. Приложение не пересчитывает.

### 6.2. Каскад «не сделали X» (только ANALYSIS)

Не интерактив. Для каждого компонента: слоты **прямо** мёртвые (`source.weekend` с его контейнерами) и **каскадно** мёртвые (`reheat` от них). Кто жив без X. В JSON набора отдельное дерево не плодить — таблица в ANALYSIS.

```json
    { "canonical_id": "chicken_thigh", "qty": 1400, "unit": "g", "title_ru": "Куриное бедро" }
  ],
  "allergens": { "contains": [], "unknown": [], "may_contain": [] }
}
```

Не писать в kit: `weekend_protocol`, `qty_g`, `eaten_by`, `eaten_by_slots`, `feeds_days`, `weekend_active_hours_estimated`, корневой `from` у слота, `container_ids` внутри `source`.

В `recipes/<slug>.md` того же прохода — черновик `steps_from_prep` списком (текст шагов) и блок «расхождение с книгой». JSON рецепта каталога не переписывать, пока человек не примет ANALYSIS.

## 8. Голос текстов

Тексты набора — для человека на кухне, не для агента. Поля: `summary`, `caution_text`, `weekend_timeline[].hands`, `weekend_steps`, `steps[].text`, `shopping[].title_ru`, `components[].title`, `containers[].label`, `storage.notes`.

Писать **литературным русским**: законченные предложения, повелительное «вы» («нарежьте», «поставьте»), обычные кухонные слова. Не телеграф, не жаргон kit (`вс`, `пн`, `слот`, `чип`, «ближний противень»).

**Так можно.** Действие, предмет, зачем на этой минуте, куда деть:

> Нарежьте перец, лук, морковь и грибы. Выложите на противень, полейте маслом, посолите и поставьте в духовку. Капусту нашинкуйте отдельно, её будете тушить на сковороде.

**Так нельзя.** Обрывки, отрицание очевидного, канцелярит, календарь чужого дня:

> Томатный соус без яиц: лук, чеснок, помидоры. Когда ложка оставляет след — с огня остывать. Яйца только во вторник.

Соус и так без яиц. Говорят: «снимите с огня и оставьте остывать». Когда есть яйца, видно по сетке блюд.

Дни недели **не писать** в воскресной подготовке и в закупке. Сетка «Блюда на неделю» уже раскладывает по дням. Всё, что нужно воскресенью, — как сделать и куда убрать (холодильник или морозилка). Подпись «на понедельник» / «варить в пятницу» в списке продуктов бесполезна у полки.

Не подменять календарём кухонный смысл. Две партии котлет — «одну в холодильник, вторую в морозилку», не «пн и чт». Два противня — чем они отличаются (перец и грибы / тыква), не «ближний» и «на четверг».

В будничном шаге можно «вчерашний борщ» и «откройте банку сейчас»: человек уже в этом приёме. Нельзя «яйца только в понедельник», «крупа в пятницу», «как в понедельник» — это расписание недели, не готовка.

Не писать «на двоих» и штучные порции в шагах («стакан на двоих», «четыре яйца»): граммы живут в закупке и боксах и масштабируются чипами 1 / 2 / 4, а тексты шагов — нет. Количество — в `qty`, не в прозе.

`title_ru` закупки — имя продукта, при нужде зачем он в блюде («Фасоль для лобио и супа»), без дня. `label` бокса — номер и содержимое, без «пн».

`caution_text` — только безопасность и то, что легко сделать не так (сырой фарш, готовый суп в воскресенье, рис заранее, охлаждение перед морозом). Не дублировать сетку. Фарш птицы и полоски: вид самой толстой + «если есть термометр — 74 °C». Не «сок прозрачный» как гарантия.

Лид воскресенья (intro шкалы): что сегодня не варить; **какая посуда понадобится** (кастрюли, сковороды, противни, сколько контейнеров).

В буднях у дня с оттайкой — явная фраза, что достать: с вечера или утром — как посчитал алгоритм по типу бокса, не одна формула «с вечера» на мясо и овощи. Для ~1 л жидкости зазор 24–36 ч.

Нельзя в текстах, которые видит человек: `вс-кастрюля`, slug, leftover, companion, «это не противень воскресенья», «не положи волокна на стол». Можно: «не из бокса», «не разогрев», «не вчерашнее», «рис варите свежим».

«Без вчерашнего»: в подписи переключателя — цена плана (+N блюд, +M позиций к закупке), не только механика. Канон экрана — [UX-PROPOSAL.md](../UX-PROPOSAL.md) §6.5. Система набора — [WEEKLY-PREP-DESIGN.md](../weekly/WEEKLY-PREP-DESIGN.md) §28–40.

## 9. Ворота качества

Стоп (переделать, не «набрать 14 слотов любой ценой»):

- слот `assemble`/`finish` без `source.kind=weekend` или без `container_ids` этого kit;
- слот `assemble`, где есть обязательная варка, прогрев или доведение до SAFETY;
- `reheat` без `source.kind=slot` / источник не вчера (`day + 1`) / «в будущем» / с непустым `container_ids`;
- слот не проходит [MEAL-CONTRACT.md](../weekly/MEAL-CONTRACT.md) (закуска как обед, мясо без растения, нет источника энергии на обеде);
- рыба/морепродукты/баранина два календарных дня подряд;
- птица/говядина/свинина три календарных дня подряд;
- борщ/суп с картофелем в морозилке ради дальнего слота;
- `container_ids` слота или альтернативы не из того же kit;
- slug слота или альтернативы не published;
- сумма `qty` контейнеров ≠ `qty` компонента;
- `weekend_protocol` / `qty_g` / `eaten_by` / `feeds_days` в JSON;
- тело «из заготовки» = вычеркнутые первые шаги без сверки;
- `reheat` у блюда, которое на второй день размокает / опасно без разбора;
- два набора с почти одним составом;
- срок хранения без пометки, что это редакционная оценка, не ГОСТ;
- `fridge_days` готового >4 (по умолчанию 3) без мороза на дальний слот;
- закрытые банки как бокс холодильника / «неделя в холоде до открытия»;
- горячий бульон, соус или мясо «сразу в морозилку» в шкале вс;
- дни недели в `weekend_timeline`, `weekend_steps`, `title_ru` закупки, `label` бокса;
- телеграф в шагах («с огня остывать», «соус без яиц», «на двоих» при масштабе порций);
- редакторский жаргон в UI (`вс-кастрюля`, «не противень воскресенья», slug, leftover);
- птица/фарш в холодильнике 7 дней без морозилки и без «Осторожно»;
- новый slug в `drafts/recipes/` в этом проходе;
- обещание вс «20 минут»;
- шкала вс без перекрытия пассив/руки, хотя у компонентов есть варка, духовка или остывание;
- альтернатива с новым компонентом / новой закупкой / без `steps` / unpublished slug;
- чистый гарнир как самостоятельный слот обеда/ужина без белка и овощей;
- слот только из овощей без белка;
- птица >4 слотов из 14;
- нет ≥2 рыбных слотов без причины, либо рыба закрыта готовым белым филе впрок / `reheat` минтая;
- рыба полностью приготовлена в вс, кроме котлет под морозилку и супа на Д1;
- рыбный суп позже Д2 обеда;
- бобовые и яйца суммарно <2 при наличии подходящих slug;
- 3+ бобовых слота подряд;
- `reheat` сметанного/йогуртового тушения, жареной картошки, омлета, красной чечевицы куском, готовой пасты через несколько дней;
- кусковой варёный картофель в морозилке;
- крупа в шкале вс без остывания пластом;
- суп/рагу ~1 л с `thaw_before_day` без запаса 24–36 ч;
- день с морозным боксом без фразы оттайки в сетке блюд (с вечера или утром — по типу бокса);
- больше 10 контейнеров;
- лид вс без списка посуды, хотя сессия на 2+ кастрюли / 2+ сковороды / 2 противня;
- ручные минуты вс занижены относительно нарезки, мойки и фасовки;
- полуготовая птица без явного «считать сырым» и целевой температуры;
- «сок прозрачный» / одна корочка как единственный признак готовности фарша птицы;
- жидкий желток объявлен одинаково безопасным;
- повтор одной заготовки два дня без смены вкуса и подачи;
- «Без вчерашнего» без цены плана в тексте переключателя;
- один белок визуально доминирует неделю (закупка + большинство слотов) без редакционной темы «неделя X»;
- неделя собрана «от заготовки к рациона», минуя [WEEKLY-PREP-DESIGN.md](../weekly/WEEKLY-PREP-DESIGN.md). Чек-лист DESIGN §23 и система §28–40 не пройдены.

## 10. После сдачи

Человек читает ANALYSIS и kit. Пилоты эксперимента №0 **не** импортировать как витрину после «принято как опыт».

Дальше отдельными фразами: новый kit по [WEEKLY-PREP-DESIGN.md](../weekly/WEEKLY-PREP-DESIGN.md); оверлей карточек «с нуля» где нужно; Terra по телам «из заготовки»; код `/prep`.
