# Оверлей осей — семейства на всех карточках

Не канон. Не волна новых slug. Канон: [RECIPE.md](../../RECIPE.md), [VOCAB.md](../../VOCAB.md), [SAFETY.md](../../SAFETY.md), [DATA-MODEL.md](../../DATA-MODEL.md). Правила осей: [README.md](README.md). Человек (чат 2026-09-06): на карточке V1 нет переключателя посуды. Это **не** «оверлей 43 не сделали». Оверлей 43 — другой слой (структура V2). Этот файл — **второй проход** `overlay_expand`, который CATALOG уже откладывал («семейство — отдельный оверлей позже»).

Старт пачки: фраза **«стартуй оверлей осей 1»** (потом 2…5). Без фразы JSON не писать.

## Зачем

Движок (`RecipeVariant`, `?equipment=`, ряд «Посуда») уже есть. На карточке ряд появляется, только если в JSON есть `variants[]` `axis=equipment` `has_delta=true` и **другой код посуды**, чем у базы. Runtime **не** додумывает «можно в духовке».

Срез 2026-09-06 (после оверлея 43 и волн 1–6):

| Где | Что уже есть | Чего нет на карточке |
|-----|----------------|----------------------|
| **Оверлей 43** | VOCAB, профиль, якорь, SAFETY, заметки списком; у 26 — **addon** с дельтой (грибы, соус, отруб) | ось **посуды**: 1 черновик; `adaptations` пустые у 32. Packet оверлея = V1 JSON, **смену посуды выдумывать было нельзя** |
| **Волны 1–6** | в packet сразу стояло `equipment_variants[]` | ~44 с видимым рядом «Посуда» |
| На `:8080` | accept+cookable накрывают V1 | 13 `revise` + 2 `reject` в БД всё ещё как ETL V1, без оверлея |

Первый оверлей **сделал V2-объект**. Второй проход — только честные `axis=equipment` + `adaptations`, не переписывать блюдо заново.

## Что агент делает

Один slug = один автор (Grok 4.6 High) → `import_draft --check --path` → Terra Medium → при `accept` импорт.

Источник правды: **Postgres**. Сначала `export_draft --slug`, не корневой V1. Автор возвращает **полный** JSON того же `id`: база почти как была + новые `variants` + согласованные `adaptations`. Не второй slug. Не «переписать блюдо ради JSON».

## Правила осей (нарушение = Major)

1. Посуда: `axis=equipment`, `has_delta=true`, `step_delta` (и `ingredient_delta`, если меняется жидкость/масло). «То же, только в казане» без других минут/крышки/жидкости — запрещено.
2. Код посуды варианта **≠** `equipment` базы. Иначе UI не рисует ряд (один код). Смена метода в той же кастрюле → `axis=addon` («Тушение»), не фальшивый `equipment=pot`.
3. Если меняется способ — `cook_method_override`. `adaptations` type `equipment` и/или `method` с теми же `from`/`to`, иначе калькулятор не предложит чип.
4. `air_fryer` / `steam`: `cook_method_override`, поле `equipment` у варианта **не** ставить (нет кода посуды). `code` = метод.
5. Мангал и электрогриль — один `grill`.
6. Добавки (`axis=addon`, `has_delta=true`) — только если состав или шаги реально другие. Соус «подойдёт» без смены списка: либо addon с дельтой (соус в ингредиентах), либо не писать. Текстовый `legacy_text` / `has_delta=false` для **этого** оверлея **не** класть: UX запретил `<details>`-абзацы.
7. Квота «ровно 3 варианта» запрещена. Нет честного другого сосуда → `equipment_variants: []` и `{ "error": "…" }` только если packet **требовал** способ, а блюдо так не готовится.
8. Не выдумывать мультиварку, микроволновку, `family_id`, `kcal`, второй `id`.
9. Птица / свинина / фарш / рыба: температуры SAFETY на **каждом** варианте способа, не только на базе.
10. Масла, бастинг, эмульсии пасты, вок-рис, фондан, салат без термообработки — **не** изобретать духовку «чтобы ряд был». Список пропуска ниже.

## Конвейер оркестратора

На один slug из **текущей** пачки:

1. `export_draft --slug` + packet пачки.
2. Task автор: `model` как в RECIPE (Grok). В промпт: этот OVERLAY-AXES (правила) + JSON packet slug + **полный текущий рецепт**. Вернуть только JSON; сохранить `id`; `editorial_tested` не ставить.
3. Записать ответ в `drafts/recipes/<slug>.json`.
4. `python manage.py import_draft --check --path <файл>`. Ошибки схемы — Composer Fast, без смены состава.
5. Terra Medium: [reviews/PROMPT.md](../reviews/PROMPT.md) + JSON. Без инструментов. Вердикт в чат.
6. `revise` → тот же автор, точечно. `reject` / Critical — стоп пачки, к человеку.
7. Импорт: `import_draft --path` после accept в чате. `--accepted` больше не нужен для запуска.

Стоп пачки: ≥1 Critical; revise > 40% пачки; автор выкинул обязательный способ без `error`.

## UI (не автор рецепта)

После пачки 1, отдельным агентом кода (не Grok-рецепт):

- Ряд «Посуда» / «Вариация» уже есть. Legacy-текст ETL — открытая секция «Вариации» списком (не `<details>`).
- Тег посуды не дублировать, если код = `cook_method` (уже в карточке).
- Чипы «Обычный / Полегче / Сытнее» — не этот оверлей (HUMAN 2.13 / PLAN спринт 6).

## Готово, когда

На `:8080` у slug пачек 1–5 ряд «Посуда» (или честный пропуск). Калькулятор с `equipment=` / сменой способа открывает **дельту**, не базу. Pytest осей зелёные. Корневой V1 не тронут.
