## Зачем два агента, не один

Полную свободу автору на структуру **не** давать: калькулятор собирает только то, что лежит в `variants` (оси `equipment` / `addon`) и `adaptations`. Нет дельты духовки — нет ответа «нет мангала → тот же шашлык в духовке». Выдуманный второй slug «в казане» ломает книгу.

Полный конспект маринада, минут и переворотов **не** писать отдельным агентом заранее: это и есть работа автора, иначе получится второй рецепт в прозе, который автор скопирует.

| Роль | Кто | Делает | Не делает |
|------|-----|--------|-----------|
| Планировщик | этот каталог / при дыре — отдельный агент | packet: оси, белок, обязательные способы, ситуации, SAFETY, что запрещено | граммы, текст шагов, состав маринада |
| Автор | Grok 4.6 High | один JSON по packet; нюансы **внутри** дельт (`time_profile`, шаги, размер куска, режим) | новый slug, чужой `protein_base`, ось «быстро» текстом без дельты |
| Валидатор | скрипт | VOCAB, SAFETY, якорь, дельты | вкус |
| Модератор | Terra Medium | `cookable` + `real` по одному JSON в промпте | читать репо, полный revise, канон VOCAB |

Автор **может** добавить 0–2 варианта сверх packet, если это закрывает ситуацию из `use_cases` (например `light` или «без грибов»). **Не может** выкинуть обязательный способ из packet без `{ "error": "почему этот способ не готовится" }`.

## Как класть «варианты» человека в модель

В БД **нет** `family_id`. Одно блюдо = один `slug`. «Семейство» — только поле packet `recipe_family` (редакционная метка для авторов и для будущей книги).

| Фраза в брифе | Куда |
|----------------|------|
| Основной: духовка / сковорода / мангал | `cook_method` + `equipment` **базы** |
| Тот же вкус, другая посуда/способ (казан, духовка, сковорода) | `variants[]` `axis=equipment`, `has_delta=true`, `cook_method_override` если метод меняется, дельты шагов и времени. Плюс `adaptations` type `equipment` или `method` с теми же `from`/`to` |
| Другой белок, то же имя («шашлык курица / свинина», «котлеты говядина / курица») | **разные slug**, одно `recipe_family`. Не addon: `protein_base` у варианта нет |
| Сорт внутри одной основы (минтай / хек / треска) | `choice_group` на якорной строке **или** addon `axis=addon`, если шаги реально разные |
| С мясом / без мяса у овощного блюда | база без мяса (`protein_base=vegetables`), addon `with_pork` / `with_chicken`. Не три slug |
| Грудка / бедро у супа | `allowed_cuts`, не чип |
| Мангал vs электрогриль | один код `grill`. Нюанс в `notes` или `equipment_note`, не два варианта |
| Духовка на шпажках vs на решётке | один `oven`; разница в шагах базы или коротком addon, не два `cook_method` |
| Полегче / меньше масла | `axis=energy` `code=light` (UI калоража не в срезе — дельту всё равно писать, если packet просит) |
| Быстро / одна посуда / на несколько дней | `use_cases` + минуты на **этом** варианте. Не чип «С перцем» |
| Аэрогриль | `cook_method_override=air_fryer`. Кода посуды `air_fryer` **нет** — поле `equipment` у варианта не ставить, `code=air_fryer`. Фильтр книги: `cook_method=air_fryer`. Не выдумывать чашу |
| Пар | то же: `cook_method_override=steam`, без новой посуды |
| Рисоварка / мультиварка | **не писать**, пока нет кода в VOCAB |

Аддоны на одном рецепте **взаимоисключающие** (база или ровно один `code`). Нельзя «грибы и фасоль» двумя чипами сразу — либо одно семейство состава, либо честно один аддон «с грибами».

## Схема packet

Минимум. Нет поля — автор возвращает `error`, не додумывает бриф.

```json
{
  "id": "транслит-title",
  "title": "Русское имя",
  "recipe_family": "shashlyk",
  "stream": "wave",
  "protein_base": "pork",
  "cook_method": "grill",
  "dish_type": "main",
  "equipment": "grill",
  "allowed_cuts": ["neck", "shoulder"],
  "anchor": "свинина, граммы, is_anchor",
  "use_cases": ["batch", "budget"],
  "situations": ["нет мангала → духовка", "мало мяса → сковорода"],
  "equipment_variants": [
    {
      "code": "oven",
      "title": "В духовке",
      "cook_method_override": "oven",
      "equipment": "oven",
      "must_differ": ["шпажки или решётка", "верхний нагрев в конце", "время"]
    }
  ],
  "addons": [],
  "adaptations_hint": ["method grill→oven", "method grill→pan_fry"],
  "energy": [],
  "safety": { "target_note": "свинина 63 °C + hold 180 или 71 °C" },
  "author_must": ["нюансы каждого способа в дельте, не в одном notes"],
  "author_free": ["состав маринада", "пропорции", "заметки 3–10"],
  "do_not": ["второй slug", "мангал и гриль как два метода", "вариация абзацем"]
}
```

`stream`: `wave` (новый slug) или `overlay_expand` (тот же id, что в V1).

## Проверка готового JSON (автор и модератор)

1. База готовится дома из супермаркета РФ. `cookable: false` → не в каталог.
2. Каждый `equipment_variants[]` из packet имеет `has_delta=true` и другие минуты/шаги, чем база. «То же, только в казане» без дельты — Major.
3. `adaptations` покрывают те же переходы, что чипы посуды. Иначе калькулятор не предложит способ, которого нет в query, через граф.
4. `time_profile` базы и осмысленные минуты в дельте способа (хотя бы в тексте шага / `timer_seconds`). Стенка духовки ≠ активное время сковороды.
5. Птица / фарш / свинина / рыба — `target_internal_temperature_c` по SAFETY.
6. Нет `duhovka`, стакана, `sol-chef.ru`, `family_id`, квоты «ровно 3».
7. Масла-шпаргалки и четвёртая целая курица в волну **не** входят.
