# Бриф для дизайна — Кухонная шпаргалка (sol-chef 2.0)

Документ для визуального дизайна и UI-полировки. **Не меняет каркас экранов.** Канон маршрутов и жестов: [UX-PROPOSAL.md](../UX-PROPOSAL.md). Живой продукт: `http://localhost:8080`. Старый сайт (V1) не референс вёрстки 2.0, только жесты и токены.

Задача дизайнера: сделать уже собранный продукт **читаемым, спокойным и «кухонным»**, не придумывать новую навигацию и не добавлять фичи.

---

## 1. Что это

**Кухонная шпаргалка** — русскоязычный кулинарный сайт без аккаунта и без фото блюд.

Человек приходит не листать красивые картинки. Он хочет:

1. **Понять, что приготовить из ситуации** (что есть дома + что сейчас важнее) — экран «Калькулятор».
2. **Найти конкретное блюдо** в книге рецептов — оглавление по основе (говядина, птица, яйца…).
3. **Готовить по шагам**, не роняя телефон в соус — режим готовки на весь экран.
4. **Свериться со справочником** — крупы (как варить), мясо (отруб → температура), советы шеф-поваров.

Это не агрегатор рецептов, не доставка, не MyFitnessPal и не TikTok-кухня. Ближе к рабочей тетради повара: тёмная бумага, чёткие числа, предупреждения, когда опасно.

Имя продукта в шапке: **Кухонная шпаргалка**. Кодовое имя репозитория: sol-chef. Домен после cutover: `sol-chef.ru`.

## 2. Для кого

| Кто | Зачем заходит | Что бесит |
|-----|----------------|-----------|
| Готовит дома 2–5 раз в неделю | «Курица есть, 40 минут, не хочу думать» | Анкета из 20 фильтров, Score 87%, пустые «скоро» |
| Ищет конкретный рецепт | «Как я делал лопатку в казане» | Четыре карточки одного жаркого («с грибами», «в духовке») как разные блюда |
| Стоит у плиты | Крупный шаг, таймер, не погас экран | Мелкий текст, прятать оглавление шагов, реклама |
| Смотрит мясо/крупу | Отруб → °C, ошибка, не эссе | Карточка без температуры, «примерно прожарьте» |
| Аллергия / осторожность | Честно: содержит / следы / неизвестно | `unknown` спрятан как «нет»; high-risk без «Осторожно» |

Язык UI — **только русский**. Коды в данных английские (`oven`, `skillet`) — на экране бытовые слова: духовка, сковорода.

Тон: спокойный, конкретный, без маркетингового восторга. «Я бы приготовил» — нормально. «Открой для себя мир вкуса» — нет.

## 3. Что уже решено (не трогать)

Каркас **D+**. Состав шапки и URL зафиксированы.

```
Шапка / таббар:  Калькулятор · Рецепты · Справочник · Советы
Бренд:           Кухонная шпаргалка  →  /
```

| URL | Вопрос экрана |
|-----|----------------|
| `/` | Что это за продукт; куда идти дальше |
| `/calculator` | Что приготовить **из этой ситуации** |
| `/recipes` | Что есть **в книге** (оглавление по основе) |
| `/recipes/<slug>` | Это семейство: состав, шаги, масштаб, КБЖУ |
| `/grains` | Как сварить крупу |
| `/meat` → `/meat/beef\|pork\|poultry` | Отруб → температура |
| `/tips` | Приём шеф-поваров |

Имя «Калькулятор» **временное** (постоянное ещё не выбрали). URL `/calculator` можно оставить. В таббаре на 320px слово длинное — терпим, не сокращать самовольно.

**Не делать:**

- Пятый пункт шапки, бургер «ещё», смена порядка пунктов.
- Главная = копия калькулятора или плоский каталог.
- Книга, которая выглядит как калькулятор (те же чипы «что есть дома»).
- Фото блюд, стоки, AI-картинки карточек.
- Заглушки «скоро», пустые гиды (море, овощи, рыба как отдельные сайты).
- Светлая тема в этом проходе (сайт тёмный по канону V1).
- Google Fonts с CDN. Шрифты — system-ui / Georgia, как в токенах сейчас; самохост Inter/Fraunces — отдельное решение, не этот бриф.
- Печать, аккаунт, корзина, граммы кладовки, фильтр «до N ккал».

## 4. Характер визуала

Настроение: **вечерняя кухня, бумага и уголь, не салон**. Тёплый near-black, не холодный #111. Акцент — золото и уголёк, не неоновый оранжевый.

Палитра уже в коде (`v2/frontend/app/styles/tokens.css`), скопирована из V1 `css/global.css`:

| Токен | Hex | Роль |
|-------|-----|------|
| `--bg` | `#1B1713` | Фон страницы |
| `--surface` | `#262019` | Карточка |
| `--surface-2` | `#322A20` | Вложенная поверхность |
| `--line` | `#3D3226` | Разделители |
| `--text` | `#EDE4D6` | Основной текст |
| `--text-dim` | `#A89A85` | Вторичный |
| `--ember` | `#C15A1F` | Жар, опасность, актив мяса |
| `--gold` | `#C9A034` | Акцент UI, фокус, «главное решение» |
| `--pork` | `#C97C6B` | Свинина (справочник) |
| `--bird` | `#D6A24A` | Птица |
| `--sage` | `#7E9463` | Крупы / «можно» |
| `--wal` | `#A6763E` | Ссылки |

Иконки: **линейные, stroke 1px, `currentColor`, viewBox 24**. Не цветные эмодзи. Спрайт `v2/frontend/public/icons.svg` (Lucide). Шапка и таббар — **иконка + подпись**, не иконка без текста.

На витрине, калькуляторе (пока нет ответа), крупах, мясе, советах, «На неделю» и книге `/recipes` — **декоративная иллюстрация в духе шпаргалки**: живописный натюрморт + тонкий «меловой» контур (температуры, кастрюля, пар, книга). Не фото блюда и не обложка карточки. На карточке `/recipes/<slug>` иллюстрации нет: готовка читается без картинки.

Карточка рецепта **без фото**. Иерархия: название → факты → аллергены мелким светло-красным текстом с заголовком «Аллергены:», не чипами → (на калькуляторе) «почему». Не обложка Instagram.

Радиусы небольшие (6–12px), не «супер-app 24px». Кнопки на телефоне — зона касания ~44px (`--touch: 2.75rem`).

## 5. Экраны — работа дизайнера

Ниже не wireframe с нуля, а **что улучшить**, не ломая смысл.

### 5.1. Главная `/` — витрина

Hero: крупное имя слева, стейк на доске с меловыми °C справа. На узком экране — отдельный мобильный кадр во всю ширину под заголовком; лид и кнопки ниже картинки, не поверх и не в узкой колонке слева. Две кнопки, сетка из 6 случайных рецептов без фото, 6 советов с линейной иконкой, футер-ссылки на гиды. На телефоне вход на главную — липкий бренд в шапке (иконка + имя), не шестой таб.

Нужно: ощущение **входа в продукт**, не админ-списка. Первичный путь — «Подобрать блюдо». Вторичный — «Все рецепты». Случайная шестёрка каждый запрос — это фича, не баг: витрина живая.

Пусто: «Рецепты пока не загружены» / «Пока нет советов» — оставить честными, не подменять каталогом.

### 5.2. Калькулятор `/calculator`

Самый важный экран продукта. Пока нет ответа — тот же кухонный натюрморт, что на витрине (кладовка). Когда есть «Я бы приготовил», картинку прячем: ответ — герой.

Слой 1 — **ситуация:** поле «что есть дома» и/или грубые чипы (курица, мясо, рыба, овощи, крупы, яйца) + сценарии: быстро, из того что есть, проще, на несколько дней, полегче, духовка.

Слой 2 — **ещё условия** по нужде (без чего, посуда). Не вываливать весь словарь.

Слой 3 — выдача **не сетка каталога:**

- **Я бы приготовил** — одно блюдо: что есть / что докупить, замены словами, почему, кнопка «Приготовить».
- **Ещё варианты** — Быстрее / Проще / На несколько дней. Не Score, не процент совпадения.

Пустой вход: только вопрос, не 98 карточек. Пустая выдача: «Ничего не подошло» + ссылка в книгу.

Слов, которых нет на этом экране: «У меня», граммы, «Точнее», полотно «Основа · Способ · Посуда».

Дизайн-задача: два визуальных регистра — **вопрос** и **ответ**. Featured крупнее альтернатив. Альтернативы — не те же карточки книги.

### 5.3. Книга `/recipes`

Вопрос: что есть в книге, не что есть дома.

1. Оглавление: плитки глав с числом семейств. Глава с нулём **не рисуется**.
2. Клик по главе — сразу все семейства. Способ и посуда — фильтры над списком, не обязательный wizard.
3. Карточка = **семейство** (один slug). Не плодить «с грибами» / «в казане» как разные блюда.
4. Поиск всегда на экране; результат — плоский список с крошками «Говядина · духовка».

Глава и калькулятор **не должны быть близнецами**.

### 5.4. Рецепт `/recipes/<slug>`

Самая плотная страница. Порядок блоков канонический (не переставлять «Осторожно» вниз):

1. Крошки: Рецепты / основа / способ / название.
2. Название. «Готовил сам» — только если редакция реально готовила (сейчас почти никогда).
3. Теги: основа, способ, тип блюда; посуда если известна.
4. **Осторожно** — high-risk, как карточка мяса с «Ошибка:», не мелкий дисклеймер.
5. Аллергены. Неизвестно ≠ нет.
6. Лид, источник, блок **Заранее** (разморозка, маринад).
7. Два **отдельных** ряда над составом:
   - **Добавки:** Базовый · С грибами · …
   - **Посуда:** Кастрюля · Духовка · Казан  
   Нет ряда — не рисовать пустые чипы. Не мешать «с грибами» и «в казане» в одну линейку.
8. Ингредиенты + блок **«У меня»** (якорь в граммах, ±, г↔кг, сброс). Порции — только если в данных есть servings.
9. Чипы калоража **Обычный · Полегче · Сытнее** — только если варианты написаны.
10. Блок **«КБЖУ ориентировочно»** после «У меня»: на рецепт; на 100 г до готовки; на 100 г готового — только если есть выход; на порцию — только если есть servings. Неполный расчёт — **заметная** пометка, не серая мелочь. Дисклеймер: «Ориентировочно. Зависит от продукта и способа приготовления.» Не ТР ТС, не диета, не рядом с «Осторожно» как медицина.
11. Шаги текущего варианта.
12. **Заметки** списком (заголовок + текст), не простыня и не `<details>`.
13. Режим готовки · Копировать ссылку.

На 390px не прятать осторожно, источник, «У меня», cook mode.

### 5.5. Режим готовки

Оверлей на весь экран. Телефон не должен гаснуть (Wake Lock).

- Setup: Сейчас / Запланировать; блок Заранее; старт.
- Шаги: огромный текст текущего шага, огромный таймер, ± пока не запущен, Назад/Далее.
- ≥769px: **две колонки** — слева шаг, справа лента всех шагов (текущий выделен, клик = прыжок). Не прятать ленту в «Все шаги».
- ≤768px: столбец как мастер; обзор «Все шаги» допустим внизу.

Внутри режима нет переключателей добавок/посуды (собьёт таймер).

### 5.6. Справочник и советы

- `/grains` — таблица/карточки крупы: вода, время, выход. Утилитарный ритм, не блог.
- `/meat` — хаб трёх белков; внутри — карточки отрубов с readout °C и блоком ошибки.
- `/tips` — аккордеон секций шеф-поваров.

Вторая полоска справочника (десктоп) / сетка 2×2 (телефон): Крупы · Говядина · Свинина · Птица. Иконки уже в спрайте: пшеница, говядина, окорок, ножка.

## 6. Компоненты, которые надо «посадить»

Это существующие куски UI, сейчас скорее функциональные:

| Компонент | Где | На что смотреть |
|-----------|-----|-----------------|
| Шапка + таббар | везде | иконка+подпись, актив, sticky, safe-area |
| Чипы | калькулятор, книга, рецепт | выбран / фильтр / ряд осей; не путать с тегом |
| Карточка семейства | книга, главная | без фото, теги, аллергены |
| Featured-решение | калькулятор | визуально главный объект страницы |
| «У меня» | рецепт | как панель инструмента, не баннер |
| КБЖУ | рецепт | 1–4 ячейки; incomplete — громко |
| Осторожно | рецепт, мясо | ember, не gold |
| Empty / error | все | одна система, без иллюстраций-заглушек |
| Cook overlay | рецепт | типографика шага и таймера — герой |

| Ширина | Поведение |
|--------|-----------|
| ≤768px | Таббар снизу (4 пункта). На рецепте: ← Рецепты \| Справка \| Режим готовки. Cook — один столбец. |

Канон шаринга подбора: `/calculator?…`. Query на `/` редиректится туда.

## 8. Контент, с которым жить вёрстке

- Каталог сейчас **~98** семейств (V1 43 + волны). Глав без рецептов нет на экране.
- У многих блюд **одна** посуда — ряда «Посуда» нет. Не рисовать фейк «можно в духовке».
- Заметки V1 часто один абзац без заголовка — один пункт списка, не выдумывать название.
- High-risk и аллерген `unknown` встречаются. Дизайн обязан их показывать, не сглаживать.
- КБЖУ — **входной набор до готовки**, не калории тарелки. Если расчёт неполный — это состояние, не ошибка вёрстки.

## 10. Критерий хорошего прохода

Дизайн удался, если:

1. За 5 секунд на главной понятно, куда жать, если «надо ужин из того, что есть».
2. Калькулятор и книга **различаются с первого взгляда**.
3. На рецепте с телефоном можно готовить: шаг, таймер, осторожно, состав — без охоты.
4. «Осторожно» и «неполный КБЖУ» нельзя пропустить; маркетинг нельзя спутать с safety.
5. Токены те же. Навигация та же. Новых экранов нет.
6. Без фото карточки не выглядят как незавершённый шаблон — иерархия названия и метаданных держит сетку.

Отдать можно: визуальные правила (spacing, type scale, состояния чипов/карточек), правки CSS/компонентов, 1–2 макета ключевых экранов (390 и 1280) поверх существующих URL. Не отдавать новую IA.
