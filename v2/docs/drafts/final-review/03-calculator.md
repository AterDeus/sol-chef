# Часть 3. Калькулятор — логика с примерами

Экран: `/calculator`. Имя в шапке временное. Это **не** книга `/recipes` и **не** блок «У меня» на карточке.

Человек сообщает ситуацию. Django собирает одно главное блюдо и 2–3 альтернативы. Next только рисует. Балл `score` человеку **не** показывают.

## Что видит человек

Пустой вход — только вопрос, без карточек.

1. Поле **Что есть дома** (плейсхолдер «курица, гречка, лук») + кнопка **Найти из этого**
2. Чипы **Что есть**: Курица · Мясо · Рыба · Овощи · Крупы · Яйца · Молочное · Другое  
   Сначала группа. Внутри — уточнение. Несколько групп не сливаются в один ряд. Сверху **Выбрано** с путём («Мясо → Говядина → фарш»).
3. **Что сейчас важнее:** Быстро · Из того, что есть · Проще · На несколько дней · Полегче · В духовке
4. Свёрнуто **Ещё условия:** Без чего (аллергены) · Посуда

После запроса:

```
[Начать заново] · [Книга рецептов]

Я бы приготовил
Боул с горбушей или тунцом
[Консервированная рыба] [Без термообработки] [8 шагов]
Всё основное уже есть          ← или «Нужно докупить: …»
Можно заменить: фета → брынза  ← если сработала замена
Почему именно это
  • можно приготовить сейчас
  • есть рыбные консервы
  • быстрее на плите
[Приготовить]

Ещё варианты
[Быстрее] Тушёные кабачки с рисом — быстрее на плите
[Проще] Боул с нутом… — меньше стоять у плиты
[Ещё вариант] …
```

Пусто: «Ничего не подошло — снимите ограничение» + ссылка **Все рецепты**.

Ошибки поля: «Не поняли: масло. Остальное учли.» / «Не удалось разобрать продукты.» Голое слово «масло» не резолвится.

## Четыре слоя движка

```
ситуация в URL → жёсткий отсев → оси семейства → замены + кладовка → балл + доска
```

### Слой 1. Жёсткий отсев (не балл)

Выкидывается, не ранжируется:

1. Не `published`.
2. Задана основа (`protein_base=`) — карточка с другой основой.
3. Задан способ — нет совпадения у базы **и** нет варианта посуды с дельтой и `cook_method_override`.
4. Задана посуда — код есть у базы **или** у варианта `axis=equipment`.
5. Задан отруб — код не в `allowed_cuts`.
6. «Без чего» — в аллергенах карточки `contains` **или** `unknown`. `may_contain` (следы) **не** отсекает.

`have=` **не** отсекает блюда, которым не хватает остальных продуктов. Нехватка уходит в «докупить». На доску **не** попадает блюдо, которое выбранный продукт **вообще не использует** (стейк при фарше).

Заготовки `sauce` / `preserve` (взбитое масло) на доску не ставят, пока в пуле есть обычное блюдо.

### Слой 2. Собрать версию семейства

Одно блюдо = один slug. Перебор: база; каждый addon с дельтой; каждая посуда с дельтой. Берётся **одна** лучшая комбинация: меньше докупать, выше балл, при равенстве — база без аддона.

Пример: боул с нутом + чип «Без тыквы» (`without_pumpkin`). Если в «Есть» нет тыквы, но есть кабачок — движок может взять этот addon.

### Слой 3. Кладовка и замены

Без `have=` слой молчит: корзины пустые, «докупить» нет.

Ядро (считается «нужно»): якорь; обязательная строка не-щепотка. Не ядро: соль, перец, вода, масло из «всегда в шкафу»; ч. л. / щепотка специй; `PANTRY_COMMON` (паприка, лавр…) — «желательно, но можно без». Лимон и уксус в ложке, ложка муки/крахмала — шкаф карточки ([04-text-rules.md](04-text-rules.md)), не закупка набора.

Всегда в шкафу, если человек не сказал иначе: вода, соль, сахар, чёрный перец, растительное масло.

Замена: правило `from → to`, `to` лежит в `have`, `forbidden=false`, качество ≥ **0.50**. Иначе строка идёт в докупку.

Корзины (в JSON; экран сеткой их не рисует):

| Корзина | Когда | На экране featured |
|---------|--------|---------------------|
| сейчас (`now`) | ядро закрыто и блюдо использует «Есть» | «Всё основное уже есть» |
| почти (`almost`) | докупить 1–2 и использует «Есть» | «Нужно докупить: …» |
| лучше (`best`) | использует «Есть», докупить больше 2 | то же, дальше в очереди |

Порядок featured: сначала блюдо из **всех** явных `have=` (≥2 продуктов), иначе сейчас → почти → лучше.

### Слой 4. Балл (человеку не показывают)

Чипы «ещё условий», если заданы:

| Сигнал | Вес | Фраза в «почему» |
|--------|-----|------------------|
| совпала основа | +10 | основа — Бобовые |
| совпал способ | +4 | совпал метод |
| совпал тип блюда | +2 | совпал тип блюда |
| совпала посуда | +2 | совпала посуда — Сковорода |
| готовил сам (редакция) | +4 | проверено редакцией |

Кладовка, если `have=` не пуст:

| Сигнал | Вес | Фраза |
|--------|-----|--------|
| ядро закрыто целиком | +10 | можно приготовить сейчас |
| совпала ядровая строка | +2 за штуку | — |
| не хватает ядровой строки | −20 за штуку | нужно докупить: … |
| каждая замена | −3 | вместо феты — брынза |
| блюдо берёт все явные `have=` (≥2) | +16 | из всего выбранного |
| бонус белка, если строка реально закрыта | +6 / рыба +8 / консервы +3 | есть куриное бедро / есть рыбные консервы |

`intent` (вес, **не** фильтр способа):

| Чип | Что делает | Фраза |
|-----|------------|--------|
| Быстро | +8 сковорода / без плиты / гриль; −3 тушение / духовка; −число шагов (до 6) | быстрее на плите |
| В духовке | +10 если способ духовка | духовка |
| Полегче | +8 если у карточки `energy_profile=light` | профиль полегче |
| Проще | −шаги (до 8); +4 духовка / тушение / без плиты | меньше стоять у плиты |
| На несколько дней | +8 тушение / духовка | можно на несколько дней |
| Из того, что есть | +12 если докупать 0; иначе −3 за каждую нехватку | из того, что есть |

Альтернативы (подписи, не балл): **Быстрее** — сковорода/без плиты/гриль и шагов не больше, чем у featured; **Проще** — духовка или тушение; **На несколько дней** — тушение; иначе **Ещё вариант**. До трёх.

## Правила адресной строки

Ключи: `have`, `have_group`, `intent`, `without`, `equipment`, плюс оси книги (`protein_base`, `cook_method`, `cuts`…) для шаринга.

- Один ключ, несколько кодов: **ИЛИ** (курица или лук).
- Разные ключи: **И** (и духовка).
- Чужой код: **400**, не тихий пропуск.
- `свинина` → группа свинины, не шея. «растительное масло» целиком. Текст с пробелами режется на слова, длинные алиасы — целиком.
- `have_group=meat` не раскрывается, если уже выбран вид (`beef`).
- Смена основы сбрасывает `cuts`. `have` не сбрасывается.
- Query на `/` уходит на `/calculator` с тем же query.

## Примеры на новых карточках

Ниже — как **должно** звучать «почему», не живой снимок БД (импорт двух leftover-slug ещё мог не пройти).

### 1. Банка рыбы, быстро

Запрос: «тунец» или чип Рыба → консервы, плюс **Быстро**.

`/calculator?have=canned_tuna&intent=fast`

- Featured: **Боул с горбушей или тунцом** (холодная сборка, `no_cook`).
- Статус: «Всё основное уже есть», если рис/овощи тоже в `have`; иначе «Нужно докупить: рис, огурец, помидор».
- Почему: «есть рыбные консервы»; «быстрее на плите» (без нагрева даёт тот же бонус, что сковорода).
- Не должен выиграть минтай в духовке: это другая основа, сырая рыба.
- Клик: `/recipes/boul-s-gorbushoy-ili-tuntsem` без посуды.

### 2. Два продукта сразу

`/calculator?have=canned_chickpeas&have=pumpkin`

- Если блюдо берёт **оба** — оно первое, фраза **из всего выбранного**.
- Кандидат: **Боул с нутом и запечёнными овощами** (якорь нут, тыква в составе).
- Тёплый боул с тыквой тоже берёт тыкву; нут там тоже есть → оба могут спорить. Побеждает тот, у кого закрыто больше ядра и выше балл; при «оба продукта в блюде» +16 одинаков — дальше покрытие и intent.

### 3. Фарш ≠ стейк

`/calculator?have=beef_mince`

- На доску **не** попадает говядина на волокна (лопатка / chuck), если фарш в составе нет.
- Фраза «есть говядина» **не** вешается за одно семейство белка. Бонус только если ядровая **строка** закрыта.

### 4. Тыква, духовка

`/calculator?have_group=veg&intent=oven` или тыква в поле + **В духовке**.

- Тёплый боул с тыквой и фетой: способ духовка, +10 «духовка».
- Боул с нутом: тоже духовка.
- Баклажаны на сковороде: штраф «Быстро» им помог бы, «В духовке» — нет.
- Featured — то, у кого закрыто ядро из овощей + вес духовки.

### 5. Почти: не хватает сыра

Есть тыква и нут, нет феты/брынзы.

- Тёплый боул: корзина «почти», «Нужно докупить: фета» (или брынза, если в составе choice).
- Если есть правило замены фета → брынза и брынза в `have` — «Можно заменить: фета → брынза», докупки нет.

### 6. Аллерген молоко

`/calculator?have=canned_chickpeas&without=milk`

- Тёплый боул с фетой **отсекается** (`contains: milk`).
- Боул с нутом (без сыра) остаётся.
- Следы `may_contain` сами по себе не режут.

### 7. Без кладовки, только сценарий

`/calculator?intent=fast`

- Корзины пустые.
- Featured всё равно собирается: вес сковороды / без плиты / гриль, штраф за длинные шаги.
- Не должно открываться взбитым маслом, пока в каталоге есть `main`.
- Кандидаты из новой пачки: боул с банкой (без плиты), баклажаны на сковороде, лобио на плите.

### 8. «Из того, что есть»

`/calculator?have=zucchini&have=rice&intent=pantry`

- Тушёные кабачки с рисом закрывают оба продукта → «из всего выбранного» + «из того, что есть», если ядро закрыто.
- Кабачок без риса: докупка риса, intent `pantry` штрафует за нехватку.

## Чего калькулятор не делает

- Не масштабирует граммы (это «У меня» на рецепте).
- Не ищет по названию (`q` только у книги).
- Не считает остатки в граммах и не ведёт корзину покупок.
- Не угадывает отруб из названия.
- Не вызывает нейросеть. Next не считает балл.
- Не показывает минуты 15/30, пока ranking не читает `time_profile` как фильтр. «Быстро» = способ + число шагов.
- Не вываливает полотно «Основа / Способ / Посуда» первым экраном.

## Как прогнать руками

1. `/calculator` — нет сетки из 43 карточек.
2. Чип Мясо открывает карточку; Говядина — вложенную с путём.
3. `?have_group=chicken&intent=fast` — одно «Я бы приготовил», не каталог.
4. `?have=canned_tuna&have=rice` — боул с рыбой первым, если оба в составе.
5. Неизвестный `have=asdfgh` → API 400 или «Не поняли».
6. Кнопка **Приготовить** открывает тот же slug с теми же осями, что на карточке решения.
