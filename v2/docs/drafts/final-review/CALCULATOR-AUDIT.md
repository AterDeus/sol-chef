# Внешний аудит калькулятора — разбор по канону

Источник: внешний аудит по [CALCULATOR-ENGINE.md](CALCULATOR-ENGINE.md), чат 2026-09-20. Ниже — не «сделать всё», а что уже правда, что ломает принятый экран, что можно чинить без смены философии.

Канон экрана: [UX-PROPOSAL.md](../../UX-PROPOSAL.md) §5 (D+: ситуация → одно «Я бы приготовил» + 2–3 альтернативы). Контракт API: [API.md](../../API.md) `GET /api/recommendations/`. Движок: [CALCULATOR.md](../../CALCULATOR.md).

Код не менять из этого файла, пока человек не скажет «стартуй».

---

## Вердикт коротко

Аудит попал в реальные дыры: время есть в каталоге и не доезжает до доски; аллергены решения — худший случай семьи; `fast` не читает минуты; подпись «Быстрее» не про время.

Часть предложений **уже канон** (intent как вес, не фильтр; featured + 2–3, не сетка). Часть **ломает D+** (три корзины вместо одной главной карточки; новые `constraint=` в query). Их не внедрять «заодно».

Снимки комбо и Django-кэш — этап 3, **после** стабильного контракта аллергенов и времени. Иначе закрепим ошибку.

## UX-предложения аудита vs D+

Согласен по смыслу карточки: крупный статус, время, «уже есть / купить / заменить / по желанию», индикатор оси, если это не база. Это **уточнение** «Я бы приготовил», не новая IA.

Не согласен без отдельного старта:

- Три блока «Можно сейчас / Почти / Другие идеи» вместо одной главной + трёх подписей. Это возврат к сетке.
- Новые query `strict=` / `constraint=` / `preference=` — новая IA первого экрана. Сейчас сценарий = вес (кроме явной оси в «ещё условиях»).
- Уровни аллергии «исключить следы» — V2.1-ish, не этот cutover.
- Переключатель курица/говядина **на доске** дублирует карточку рецепта. Канон: клик открывает ту же ось на `/recipes/slug?variant=`. На доске достаточно строки «Основа: говядина», если не база.

«Один slug — одно решение» оставляем. Прятать более удобный чип плохо; лечится статусом на карточке («есть вариант с курицей — 0 докупок»), не второй строкой в списке.

## Ранжирование — этап 2, не «заодно»

Разделение предпочтение / требование — здравое, но это новый контракт query. Пока intent мягкий — это канон CALCULATOR, не баг.

Вес missing по типу строки: якорь/`is_anchor` vs овощ vs специя. Словарь «редкий соус» в VOCAB нет. Можно опереться на уже существующее: `is_anchor` сильнее, pinch/tsp уже не ядро, common уже не missing. Новый вес «дорого/редко» — только после списка человека.

Три уровня замен (точно / с заменой / компромисс) — копирайт + пороги quality. Сейчас порог один 0.50. Метки «равноценная / подходящая / компромиссная» — редакционная таблица, не выдумывать из float на лету без сида.

## Данные

Валидатор оверлея уже блокирует обязательную строку без `canonical_id`. Добор аудита, который ещё не в draft.py:

- нет `time_profile` — **уже** error оверлея (`test_missing_time_profile_fails`). ETL V1 мог принести null — ranking тогда не врёт минутами, просто не показывает.
- `servings` для batch — сейчас batch смотрит способ, не порции. Не блокировать публикацию, пока intent не читает servings.
- карточка с разными аллергенами у вариантов — ловится, если на доске начнём отдавать комбо.

Прогон живого каталога на сироты id / null time / energy_profile=standard при наличии ккал — отдельная команда, не смешивать с солвером.

## Производительность

Согласен с направлением. Порядок:

1. Сначала починить контракт (время, аллергены комбо, ядро без пустого id, честный копирайт).
2. Потом snapshot: ядро, common, аллергены **комбо**, method, equipment, step_count, минуты.
3. Rank по множествам; `assemble` только top-4.
4. Django cache keyed by canonical query + `catalog_revision`. Next `revalidate: 60` не замена.
5. Пустой `GET /api/recommendations/`: idle без солвера. Экран уже не зовёт; API всё ещё платит.
6. Suspense доски — perceived, не ускорение Django.

Эквивалентность snapshot ≡ assemble — тесты U15/U15b/U20–U22 плюс аллергены и минуты комбо.

Не кэшировать до пункта 1: закэшируем семейное молоко на говяжьем чипе.

## Этап 1 — сделано (чат 2026-09-20)

Без новых ключей query, без трёх сеток, без snapshot. Остальное из списка ниже — в коде.

1. `serialize_solution`: `time_profile` {total, active} с **собранного** рецепта; UI рисует, если не null.
2. Аллергены featured/alts = assemble комбо; `without` семейный худший пока не трогать.
3. `is_core_line`: нет `canonical_id` → не ядро, не докупка. Аудит каталога списком.
4. Статус карточки: now без замен / now с заменами / докупить N. Не врать «всё есть» при substitutions.
5. Подпись альта «Быстрее» только при меньшем `total_minutes`; иначе «На плите» / «В духовке» по method.
6. `fast`: мягкий сигнал по `time_total_minutes` комбо (меньше — выше), **без** жёсткого отсева, пока нет порога в DEFAULTS.
7. Свести DEFAULTS/CALCULATOR/API к этому алгоритму. Тест: время есть в JSON решения; аллергены чипа ≠ худший случай, если дельта снимает молоко; пустой id не в `shopping_delta`.

Не в этапе 1: `constraint=`, `kcal_max`, SolutionBuckets на экране, два pantry-intent, уровни «следы», Django cache, snapshot.

## Этап 3 — сделано (чат 2026-09-20)

Без трёх сеток, без `constraint=` / `preference=` / `strict=`, без `kcal_max`. Снимки после этапа 1, чтобы не закэшировать семейное молоко.

1. Пустой `GET /api/recommendations/`: `featured: null`, **без** queryset каталога и без солвера.
2. `Recipe.axis_snapshots` (миграция `0010`): ядровые id, аллергены комбо, method/equipment, шаги, минуты. Rank по снимкам; `assemble` только если снимка нет. Импорт/save и `rebuild_axis_snapshots` пересчитывают. Локально 255 семейств.
3. Django locmem 45 с, ключ = канонический query (`rec:v4:`). `catalog_revision` в ключ не клал: TTL и рестарт снимают. После импорта доска может быть старой до 45 с.
4. `Suspense` вокруг доски: форма уходит отдельно от солвера. Perceived, не ускорение Django.

Смоук локально (`:8080`): пустой API ~6–45 мс; `have_group=chicken&intent=fast` первый ~100 мс, повтор ~21 мс; HTML калькулятора с query ~115 мс TTFB. Доска D+: одно featured + 3 альта, `time_profile` на решении. На ВМ выложено без push `main`: idle с самой ВМ ~8 мс, снаружи пустой API ~0.27 с (было ~1.2), `have_group`+`intent` первый ~0.80 с / повтор ~0.24 с (было ~1.8 HTML), главная ~0.30 с.

Замки: U15–U22 без смены смысла; U41 idle; U42 `snapshot_fits` + rank по снимку без `assemble`. `tests/test_solve.py` 23 passed.

Не в этапе 3: три корзины на экране, второй pantry-intent, уровни «следы», DNS/cutover.
