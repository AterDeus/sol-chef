# Справочник единиц и кодов (приложение 2.0)

Канон структуры рецепта для сайта и калькулятора (HUMAN §2). Старые коды V1 (`duhovka`…) в продукт не копировать. ETL со старых файлов — по таблицам «было → стало» внизу.

## Units (`unit`)

| Код | Значение |
|-----|----------|
| g | граммы |
| kg | килограммы |
| ml | миллилитры |
| l | литры |
| pcs | штуки |
| tsp | чайная ложка (5 мл) |
| tbsp | столовая ложка (15 мл) |
| pinch | щепотка |
| clove | зубчик |
| bunch | пучок |
| slice | ломтик |
| to_taste | по вкусу (без amount) |

Не использовать свободные строки вроде `зубчиков`, `стакана`, `банка` — нормализовать к enum.

`cup` / стакан в рассчитываемых строках запрещён. `tsp` = 5 мл, `tbsp` = 15 мл. `pinch` и `to_taste` — `amount` в БД `NULL`, `scalable=false`; в количественном матчинге не участвуют. В КБЖУ не входят (не `incomplete`); иконка на карточке только у жирного/сладкого, не у соли (DEC-024). Сравнение с кладовкой в граммах — только если у канонического ингредиента есть плотность (г/мл); иначе учитывать факт наличия, не количество.

## scale_mode и scalable

Не плодить поле `scalable_rule`. Два поля, не одно:

- `scale_mode`: только `linear` \| `gentle` \| `whole` \| `manual`. Значения `fixed` **нет**.
- `scalable`: bool. `false` → amount не меняется, `scale_mode` не применяется.

Таблица SAFETY «`fixed`» = этот `scalable=false`.

| `scale_mode` | Формула (если `scalable=true`) | Когда |
|--------------|--------------------------------|--------|
| `linear` | `× ratio` | белок, овощи, крупа, вода в супе |
| `gentle` | `× ratio^0.7` | соль, сахар-приправа, перец, специи, масло «для сковороды» |
| `whole` | округление до целых | яйца, лавровый лист, штучный чеснок |
| `manual` | не авто-масштаб | разрыхлитель, дрожжи, желатин; сода в выпечке |

`scalable=false`: щепотка, по вкусу, «смазать форму», фиксированный стейк без граммов.

`ratio` из порций **или** якоря «У меня» (`is_anchor` — DATA-MODEL). Температуры, `pull`/`target`, hold и таймеры шагов не масштабируются. Соль при 2→10 порциях не умножать на 5.

## Поля шага: температуры

| Поле | Смысл |
|------|--------|
| `pull_internal_temperature_c` | Снятие с огня; может быть на 2–5 °C ниже цели |
| `target_internal_temperature_c` | Безопасный конец (после отдыха, если он есть) |
| `hold_seconds` | Выдержка; для свинины 63 °C минимум 180 |

Валидатор смотрит **target**, не pull. Подробности и минимумы — [SAFETY.md](SAFETY.md).

## Аллергены (коды)

Те же 14: `gluten`, `milk`, `egg`, `fish`, `crustacean`, `mollusc`, `peanut`, `tree_nut`, `soy`, `sesame`, `mustard`, `celery`, `sulfite`, `lupin`.

Флаг висит на **`canonical_id`**, не на подстроке «молоко»/«мука». `fish` ≠ `crustacean` ≠ `mollusc`. Сельдерей обязателен в модели. Эвристики и исключения — SAFETY.

## High-risk флаги рецепта

`raw_egg`, `raw_meat`, `raw_fish`, `raw_milk`, `wild_mushrooms`, `ground_meat`, `preservation`, `fermentation`, `child_food`, `fire_hazard`, `poultry_temp`.

Whitelist культивируемых грибов и сырые мясо/рыба/молоко — SAFETY.

## protein_base — основа блюда (V2, HUMAN §2.1)

Верхнеуровневый код **основы блюда** (книга, ETL, внутренний query). На первом экране калькулятора словарь не вываливать (DEC-018). Коды — латиница; в UI — русские названия.

| Код | Русское название | Что входит |
|-----|------------------|------------|
| `beef` | Говядина и телятина | Мясо, фарш |
| `pork` | Свинина | Мясо, фарш, бекон |
| `poultry` | Птица | Курица, индейка, утка |
| `lamb` | Баранина | Баранина, ягнятина |
| `fish_white_sea` | Белая морская рыба | Треска, минтай, хек, сибас, палтус |
| `fish_red_sea` | Красная рыба | Лосось, семга, форель, горбуша |
| `fish_river` | Речная рыба | Судак, щука, карп, окунь |
| `fish_canned` | Консервированная рыба | Промышленные консервы: тунец, горбуша, сардины в банке. Не сырое филе и не `raw_fish`. Если в блюде банка и свежий лосось не основа — этот код, не `fish_red_sea` из-за первой строки |
| `seafood` | Морепродукты | Креветки, кальмары, мидии, осьминог |
| `offal` | Субпродукты | Печень, язык, сердечки |
| `eggs_dairy` | Яйца и молочные | Сырники, омлеты, запеканки — когда это основа блюда |
| `vegetarian` | Растительная / без мяса | **Только ETL V1** и смешанные блюда без одной основы. Новые рецепты — коды ниже, не этот |
| `vegetables` | Овощи | Картофель, капуста, кабачок, баклажан, тыква, свёкла, морковь, томат, перец, лук как основа блюда |
| `mushrooms` | Грибы | Шампиньоны, вешенки, шиитаке, эринги. Иные → `wild_mushrooms` + человек |
| `legumes` | Бобовые | Чечевица, нут, фасоль, горох, маш — когда это основа, не гарнир в мясе |

Омлет / сырники → `eggs_dairy`, не `vegetables`. Креветки → `seafood`, не рыба. Печень куриная → `offal`, не `poultry`. Рагу из кабачков → `vegetables`. Нут с томатом → `legumes`. Жульен → `mushrooms`.

Книга `/recipes`: первый уровень — группы по смыслу (мясо / птица / овощи / рыба и морепродукты / гарниры / завтраки / десерты / другое), не алфавит `protein_base`. Завтрак (`dish_type=breakfast`) важнее основы: яичница не в «другом». Состав групп — [UX-PROPOSAL.md](UX-PROPOSAL.md) §4. Коды в JSON и API не меняются.

Коды `vegetables` / `mushrooms` / `legumes` — основа **блюда** в книге, не ряд «что есть дома». Словарь домашней закупки — [CALCULATOR.md](CALCULATOR.md) / `pantry_vocab.py` (DEC-019), не этот список.

Коды `vegetables` / `mushrooms` / `legumes` — по запросу человека 2026-09-05 (меню калькулятора). Пока нет явного «нет» в HUMAN 2.14. Диета «без мяса» — не этот словарь, а раздел «Диеты» ниже.

## cook_method — способ приготовления (V2, HUMAN §2.2)

«Как готовим» (жарка, тушение, варка). Не путать с `dish_type` (роль на столе) и с `equipment` (сосуд). Коды `pan_fry` / `stew` / `grill` живут **только здесь**, не в типе блюда и не в посуде. `?cook_method=oven` и `?equipment=oven` — разные ключи, разные словари.

| Код | Русское название | Бытовой смысл |
|-----|------------------|---------------|
| `oven` | В духовке (запекание) | Запекание, выпечка, ростинг |
| `pan_fry` | На сковороде (жарка) | Быстрая жарка, пассерование, соте |
| `stew` | Тушение и томление | Медленная готовка в соусе/бульоне, казан |
| `boil` | Варка в кастрюле | Варка в воде/бульоне, супы |
| `grill` | Гриль и мангал | Открытый огонь, электрогриль, решётка |
| `steam` | На пару | Пароварка, мантоварка |
| `no_cook` | Без термообработки | Салаты, холодные закуски, тартары, сборка |
| `air_fryer` | Аэрогриль | Чаша аэрогриля; не путать с `oven` |
| `deep_fry` | Во фритюре | Масло покрывает продукт; не `pan_fry` |

`air_fryer` и `deep_fry` — черновик 2026-09-05, в V1 нет. Мультиварка и микроволновка — не метод и **не** в коротком enum посуды ниже (пока нет блюд).

## equipment — посуда (V2, HUMAN 9.2 / 2.5)

Сосуд или камера, в которой лежит еда. Не нож, не доска. Не путать с `cook_method`. На рецепте — **отдельный** переключатель от добавок («с грибами»). Пустое поле — у `no_cook`, если сосуда нет.

| Код | В UI | Бытовой смысл |
|-----|------|----------------|
| `pot` | Кастрюля | Плита, крышка, суп / варка / тушение |
| `oven` | Духовка | Камера духовки |
| `kazan` | Казан | Толстые стенки, плов / томление |
| `skillet` | Сковорода | Открытая жарка, соте |
| `saucepan` | Сотейник | Высокие борта, соус, ризотто |
| `baking_dish` | Форма | Форма / жаровня в духовке |
| `grill` | Гриль | Решётка, мангал, электрогриль как сосуд |

Типичные пары (не CHECK): `pan_fry`→`skillet`; `boil`→`pot`; `stew`→`pot` или `kazan`; `oven`→`oven` (+часто `baking_dish`); `grill`→`grill`.

Когда меняются время, жидкость, крышка или метод — ось варианта `equipment` (DATA-MODEL). Тот же сосуд, предостережение в шаге — `equipment_note`, без переключателя.

ETL V1 (дефолт базы, **без** оси вариантов посуды; казан vs форму не угадывать):

| Папка / метод V1 | `equipment` |
|------------------|---------------|
| `skovoroda` | `skillet` |
| `kastryulya` | `pot` |
| `duhovka` | `oven` |
| `tushenie` | `pot` |
| `grill` | `grill` |

Не кодировать технологию (жарка, варка, запекание). Стейк на сковороде: `dish_type=main` + `cook_method=pan_fry`.

| `salad` | Салат | Тёплые и холодные салаты |
| `appetizer` | Закуска | Бутерброды, канапе, паштеты, нарезки |
| `breakfast` | Завтрак | Каши, сырники, блюда из яиц |
| `side` | Гарнир | Пюре, крупы, тушёные/запечённые овощи |
| `pasta_grains` | Паста и крупы | Паста, ризотто, плов, лапша как самостоятельное блюдо |
| `bakery` | Выпечка несладкая | Пироги, пицца, киши, хлеб |

## Калораж варианта (`energy_profile`)

КБЖУ — отдельный расчёт входного набора (`raw_input`), не этот профиль. `energy_profile` по-прежнему не ккал. Числа ккал в JSON автора не выдумывать. Один рецепт, тот же вкус, другой набор количеств и приёмов.

| Код | В UI | Смысл |
|-----|------|--------|
| `standard` | Обычный | Как готовим по умолчанию |
| `light` | Полегче | Меньше жира и/или сахара; тот же блюдо; можно смена метода (жарка → духовка/пар) |
| `rich` | Сытнее | Больше масла, сливок, сахара — если вариант написан |

Правила:

- Дефолт тела рецепта — `standard`. Нет варианта — переключатель не показывать.
- `light` / `rich` — дельты ингредиентов и шагов + `allergen_delta`, не второй slug.
- Вкус узнаваемый: те же специи и основа. Не подменять стейк куриным бульоном.
- Числа ккал не выдумывать в JSON автора. КБЖУ карточки — производное (DEC-022), не этот код.
- Не медицинская «диета». High-risk варианта — свой флаг и «Осторожно».
- Масштаб (`gentle` и якорь «У меня») считается **после** выбранного профиля, в Django.
- Query: `?energy=light` (с `servings` / `anchor_weight`).

V1 при ETL: только `standard`, `light` не выдумывать.

## Сценарии решения (`use_cases`)

Не теги V1 и не `dinner` / `cozy` / `asian`. Только факторы, которые калькулятор может поднять в выдаче.

| Код | Русское | Смысл |
|-----|---------|--------|
| `fast` | быстро | мало стены, мало активного времени |
| `easy` | просто | низкий `effort_level` |
| `pantry` | из запасов | мало покупок |
| `one_pan` | одна посуда | низкий `washing_level` / одна сковорода или противень |
| `batch` | заготовка | порция впрок |
| `budget` | дешевле | недорогой набор |
| `light` | полегче | не путать с осью `energy=light` (та — написанная дельта состава) |

Автор ставит код только если рецепт **реально** подходит. Пустой список лучше ложного `fast`.

## Адаптации (`adaptations`)

Не `variants`. Движок применяет только то, что редактор разрешил.

| `type` | Поля | Пример |
|--------|------|--------|
| `substitution` | `from`, `to`, `quality?` 0–1 | `sour_cream` → `yogurt` |
| `omission` | `ingredient`, `quality?` | убрать петрушку |
| `equipment` | `from`, `to` из equipment, `quality?` | `skillet` → `oven` |
| `method` | `from`, `to` из cook_method, `quality?` | `pan_fry` → `stew` |

## Диеты (diet, черновик)

HUMAN 2.6 пуст. Это фильтр ограничений, не основа блюда.

| Код | Русское | Не путать с |
|-----|---------|-------------|
| `vegetarian` | Без мяса, птицы, рыбы | `protein_base=vegetables` |
| `vegan` | Без животных продуктов | яйца/молоко тоже нет |
| `fasting` | Постный стол (православный пост как бытовой смысл) | не сертификат |
| `gluten_free` | Без глютена в составе | `unknown` глютена = отсев |
| `dairy_free` | Без молока | то же для `milk` |

Кролик, дичь, колбаса как отдельные `protein_base` **не** вводим: кролик → очередь человеку; колбаса/бекон → `pork` или `beef`. Морепродукты не дробить как рыбу (креветка/мидия — теги или канон ингредиента, чип один: `seafood`).
