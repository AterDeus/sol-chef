## Калькулятор и единицы

- Источник словарей: `v2/docs/VOCAB.md` (HUMAN §2). Рецепты агентами: `v2/docs/RECIPE.md`.
- `scale_mode`: `linear` \| `gentle` \| `whole` \| `manual`. Отдельно `scalable` bool. `scalable=false` → amount не меняется, `scale_mode` игнорируется. Слова `fixed` в enum **нет** (это и есть `scalable=false`). Не поле `scalable_rule`.
- `gentle`: `amount * ratio^0.7`. **Не** формула V1 `1 + (ratio-1)*0.5` из `js/ingredient-utils.js`.
- `ratio` = `new_servings/base_servings` **или** `target_anchor/base_anchor` («У меня»). Один сервис. Оба query сразу — 400.
- Соль, острые специи, приправы, масло «для сковороды» по умолчанию `gentle`. Разрыхлитель, дрожжи, желатин — `manual`. Сода в бархате/маринаде — `linear` (пропорция к мясу); в выпечке — `manual`. Не автодетект V1 `gentle`.
- Карточка рецепта: «У меня» считает количества **на клиенте** тем же правилом, что Django (`ratio^0.7`, округление DEFAULTS). Запрос на каждый шаг слайдера не делать. Ранжирование калькулятора — только Django.
- Температуры, `pull`/`target`, выдержка, таймеры шагов **не** масштабируются.
- Нет якоря и нет servings → масштабирование выключено, порции не выдумывать при ETL.
- `yield_weight_g` в знаменателе `per_100g_cooked` — `yield * ratio`, всегда linear. Нет ключа — ячейки нет. Не выдумывать выход на ETL V1 / оверлее 43.
- Расчёт количеств в кладовке: только после приведения к одной размерности; нет плотности — сравнивать факт наличия, не граммы.
- Стакан/`cup` в рассчитываемых строках рецепта запрещён.
- Счёт в Decimal. Округление для UI (порт `roundScaled`): г/мл ≥200 → шаг 10; ≥50 → шаг 5; иначе целое. кг/л — 2 знака. шт — 0.5, min 0.5 (`whole` — целое, min 1). ч.л./ст.л. — четверти.
- КБЖУ: считать Decimal **до** округления, по resolved amount после `apply_mode`, не по `roundScaled` количеств. Отображение: ккал — целое; белок/жир/углеводы — один знак после запятой. `to_taste` / `pinch` не в сумме и не `incomplete`; иконка только у жирного/сладкого, не у соли (DEC-024).

## Веса ранжирования калькулятора (v0)

Числа в конфиге, не в UI. Как собирается решение — [CALCULATOR.md](CALCULATOR.md).

| Сигнал | Вес |
|--------|-----|
| Жёсткий фильтр (аллерген contains/unknown, unpublished, нет основы/посуды/способа) | отсев, не балл |
| Совпала выбранная основа | +10 |
| Совпал выбранный способ | +4 |
| Совпал выбранный тип блюда | +2 |
| Совпала выбранная посуда | +2 |
| `editorial_tested` | +4 |
| Ядро закрыто из `have` (сейчас) | +10 |
| Совпала ядровая строка из `have` | +2 |
| Не хватает ядровой строки | −20 |
| Каждая применённая замена (трение) | −3 |
| `have=` не задан | pantry-веса = 0 |

Бонус «есть …» по семейству белка (+6 / рыба +8) — только если ядровая строка из `have` реально закрыта. Фарш не закрывает стейк, лопатку и рёбра. Блюда с нулевым покрытием ядра на доску не попадают. Два и больше явных `have=` — блюдо, которое берёт все, получает +16 и идёт первым.

`sauce` / `preserve` (масло, соус-заготовка) на доске калькулятора ниже любого блюда: не featured и не «Быстрее», пока в пуле есть `main` / `soup` / `breakfast` / `side` / … Если в пуле только заготовки — они остаются.

Порог `quality` замены: **0.50**. Ниже — не подставлять. `forbidden` — никогда. Специи (`tsp` / щепотка), соль, перец, вода, лавр — не входят в «докупить». Строка «по вкусу» у ядра блюда — входит.

Граммы кладовки (+5 «количества хватает») — V2.2, не этот спринт. Диета / бюджет / pairing — нет в UI, веса не считать. Не ставить `kcal_max` в веса калькулятора.

## Всегда в шкафу (`PANTRY_ASSUMED`)

Считать имеющимся, если человек не сказал обратного: `water`, `salt`, `coarse_salt`, `sugar`, `black_pepper`, `vegetable_oil`.

`PANTRY_COMMON` (паприка, лавр, зира, соевый соус…) — часто есть, но **не** подставлять автоматически; отсутствие не убивает рецепт, в «почему» можно «желательно».

`water_or_stock` и подобные — не товары, не assumed. Словарь покупки: `v2/backend/apps/recipes/pantry_vocab.py`, не `protein_base`.

## Поиск

`to_tsvector('russian', normalize_ru(...))` + `pg_trgm`. `unaccent` в init Postgres есть, но **не** переводит `ё`→`е` — только `normalize_ru`. Поля вектора — DATA-MODEL. Конфиг `simple` не использовать для русских полей.

## Auth

- GET по ссылке из письма **не** создаёт сессию и **не** сжигает токен.
- Вход: страница подтверждения, POST кнопки «Войти» или POST 6-значного кода.
- Next.js Server Components / Server Actions пробрасывают `Cookie` и CSRF на Django явно.
- Браузерный клиент ходит на `/api/` того же домена (прокси на Django), без CORS и без JWT.
- Сессии в Postgres. Пользователь создаётся на первом успешном POST confirm.
- **Только российская почта.** Запрещены Gmail, Outlook, iCloud и прочие зарубежные ящики. Разрешённый список по умолчанию: `yandex.ru`, `ya.ru`, `yandex.com` (Яндекс), `mail.ru`, `bk.ru`, `inbox.ru`, `list.ru`, `internet.ru`, `rambler.ru`. Доп. домены — только записью в конфиге. Флаг включён (HUMAN 6.3); юрист 406-ФЗ ещё не смотрел.
- Смены email нет. `trusted` выдаёт модератор.
- Капчи нет; rate limit IP+email через Redis.
- Фото: max 8 МБ, ≤20 Мп; ClamAV не ставить. HEIC через pillow-heif либо отказ.

## Контент

- High-risk (сырое, дикие грибы, консервация, птица…): в каталог **можно** после доп. модерации; на странице обязателен блок «Осторожно». Не в детские подборки. Агент не публикует сам.
- Контент с внешнего источника: можно при **указании автора/сайта и ссылке**, проверке что рецепт воспроизводимый, не выдумка модели. На сайте уведомление: можно написать на почту, чтобы материал убрали. Это продуктовое правило; юрист копирайт/152 ещё не смотрел.
- Цель каталога: текущие рецепты V1 (таблица «Каталог V1» выше) **плюс** новая сотня, не «43 внутри 100».
- Калораж рецепта — редакционные профили `standard` / `light` / `rich` (не «минус 20% ккал»). Плюс ориентировочное КБЖУ входа (DEC-022); если задан `yield_weight_g` — ещё на 100 г готового (DEC-023). Не лаборатория.

## Деплой

- Сборка образов **только в CI**, на VPS — `docker compose pull && up -d`.
- Migrate — один раз до переключения web, не из Celery.
- На VPS: Timeweb, RAM **8 ГБ**, swap **4 ГБ**.
- Production secrets не в git; CI (GitHub Actions) не имеет доступа к production data.
- Backup: `pg_dump` сутки, 7 дней, бакет не тот же, что медиа. RPO 24 ч / RTO 4 ч — с запуска, не с первого среза.
- Код 2.0 только в папке `v2/`. В `main` не пушить прод, пока не попросили.
