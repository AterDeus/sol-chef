# Кухонная шпаргалка — как сайт работает для человека

Одностраничник продукта для внешнего аналитика, дизайнера или подрядчика. Здесь сценарии, экраны и один полный рецепт так, как их видит пользователь.

Это **не** канон для разработки. Если этот файл расходится с [UX-PROPOSAL.md](UX-PROPOSAL.md), [DATA-MODEL.md](DATA-MODEL.md) или [API.md](API.md) — верны они. Карта остальных документов: [README.md](README.md).

Имя в шапке: **Кухонная шпаргалка**. Кодовое имя репозитория: sol-chef. Домен после cutover: `sol-chef.ru`. Язык интерфейса — только русский.

Живой срез 2.0 (локально): http://localhost:8080 после `docker compose -f v2/infra/docker-compose.yml up --build`.

---

## 1. Что это

Русскоязычный кулинарный сайт **без аккаунта, без фото блюд и без рекламы**. Человек приходит не листать картинки. Он хочет одно из четырёх:

1. **Понять, что приготовить из ситуации** — что есть дома и что сейчас важнее (быстро, без покупок, духовка…). Это экран «Калькулятор».
2. **Найти конкретное блюдо** в книге рецептов — оглавление по смыслу стола, не по кладовке.
3. **Готовить по шагам**, не роняя телефон в соус — полноэкранный режим готовки с таймером.
4. **Свериться со справочником** — как варить крупу, какой отруб до какой температуры, приёмы Энди.

Это не агрегатор рецептов, не доставка, не трекер калорий и не соцсеть. Ближе к рабочей тетради: тёмная бумага, числа, предупреждение, когда опасно.

**Сознательно нет:** фото блюд, стоки, «скоро», печать, корзина магазина, фильтр «до N ккал», рейтинг в процентах, вход через Google/Госуслуги.

## 2. Две версии в одном репозитории

| | Сейчас в проде | То, о чём этот файл |
|--|----------------|---------------------|
| Код | корень репо (`index.html`, `data/`) | папка `v2/` |
| Как устроено | статический HTML + JSON в браузере | Next.js читает Django, Django держит PostgreSQL |
| URL рецепта | `recipe.html?id=…` | `/recipes/<slug>` |
| Подбор ужина | нет | `/calculator` |
| Смотреть | `python -m http.server 3456` из корня | http://localhost:8080 |

Публичный сайт `sol-chef.ru` пока ещё **V1**. Новый продукт — V2; cutover на тот же домен, когда человек скажет переносить. Старые ссылки `recipe.html?id=` на V2 редиректят на `/recipes/<slug>`.

## 3. Для кого

| Кто | Зачем заходит | Что бесит |
|-----|----------------|-----------|
| Готовит дома 2–5 раз в неделю | «Курица есть, 40 минут, не хочу думать» | Анкета из 20 фильтров, Score 87% |
| Ищет знакомое блюдо | «Как я делал лопатку в казане» | Четыре карточки одного жаркого («с грибами», «в духовке») как разные блюда |
| Стоит у плиты | Крупный шаг, таймер, экран не гаснет | Мелкий текст, реклама |
| Смотрит мясо или крупу | Отруб → °C, типичная ошибка | «Примерно прожарьте» |
| Аллергия / осторожность | Честно: содержит / следы / неизвестно | Неизвестное спрятано как «нет»; птица без «Осторожно» |

Тон: спокойный, конкретный. «Я бы приготовил» — нормально. «Открой для себя мир вкуса» — нет. Коды в данных английские (`oven`, `skillet`); на экране — духовка, сковорода.

## 4. Каркас: куда человек ходит

Шапка на десктопе и нижний таббар на телефоне — **одни и те же четыре пункта**, иконка + подпись:

**Калькулятор · Рецепты · Справочник · Советы**

Логотип «Кухонная шпаргалка» ведёт на главную `/`. Состав пунктов не менять: пятой вкладки нет.

```
/                    витрина: что это; куда идти дальше
/calculator          что приготовить из этой ситуации
/recipes             книга: что есть в каталоге
/recipes/<slug>      одно семейство блюда
  + режим готовки    полноэкранный wizard шагов
/grains              как сварить крупу
/meat                выбор: говядина / свинина / птица
/meat/beef|pork|poultry   отруб → температура
/tips                приёмы Энди
```

Имя «Калькулятор» **временное** (постоянное ещё не выбрали). URL `/calculator` можно оставить.

На телефоне (≤768px) на карточке рецепта своя полоска: ← Рецепты · Справка · Режим готовки.

Гостевой срез **без входа**. Страницы `/login` и `/account` заложены на следующий релиз (избранное, «я приготовил», кладовка). Гость уже умеет подобрать, открыть рецепт, масштабировать и готовить.

## 5. Сценарии

### 5.1. Не знаю, что готовить → `/calculator`

Вопрос экрана: **что приготовить из этой ситуации**. Не каталог. Не анкета из словарей.

Человек сообщает:

1. **Что есть дома** — свободный текст и/или грубые чипы: курица, мясо, рыба, овощи, крупы, яйца, молочное. Выбранная группа раскрывается (мясо → вид → отруб). Граммов кладовки нет: факт наличия, не «у меня 400 г фарша».
2. **Что сейчас важнее** — быстро / из того что есть / проще / на несколько дней / полегче / духовка. Это вес, а не жёсткий фильтр способа (кроме явного выбора в «ещё условиях»).
3. **Ещё условия** (по нужде, не с первого экрана) — без чего (аллергены), посуда.

Пустой вход — только вопрос, не сетка всех рецептов.

Выдача **не** каталог с процентом совпадения:

- **Я бы приготовил** — одно блюдо: что уже есть, что докупить, замены словами, почему, кнопка «Приготовить».
- **Ещё варианты** — человеческие подписи вроде «Быстрее» / «Проще» / «На несколько дней», не Score.

Клик открывает ту же версию семейства (добавки и посуда уже выбраны). Ничего не подошло — «снимите ограничение» и ссылка в книгу. Слово «скоро» не пишем.

Ссылка в адресной строке — готовый подбор, её можно скинуть. Query на главной `/` уезжает на `/calculator` с тем же query.

«У меня» на карточке рецепта — **другой** жест: масштаб этого блюда под кусок мяса, который уже лежит. Не путать с калькулятором.

### 5.2. Ищу конкретное блюдо → `/recipes`

Вопрос экрана: **что есть в книге**, не «что есть дома». Книга и калькулятор не должны выглядеть одинаково.

Оглавление — **восемь разделов в этом порядке**:

| Раздел | Что внутри |
|--------|------------|
| Мясо | говядина, свинина, баранина, субпродукты — если это не завтрак/гарнир/десерт |
| Птица | курица и прочая птица |
| Овощи | овощи, грибы, бобовые как основное блюдо, не гарнир |
| Рыба и морепродукты | рыба и море |
| Гарниры | роль на столе «гарнир» |
| Завтраки | яичница, омлет, сырники, каша… |
| Десерты | десерты |
| Другое | соусы, заготовки и то, что не легло выше |

Яичница живёт в **Завтраках**, не в рыбе и не в «другом». Один рецепт — в одном разделе. Пустой раздел после загрузки данных **не показывается** (нет плитки «скоро»).

Как листать:

1. `/recipes` без выбора — плитки разделов с числом семейств.
2. Клик по разделу — **сразу все блюда главы**. Способ и посуда — фильтры сверху, не обязательный второй шаг. Если в главе несколько основ (говядина / свинина) — узкий фильтр «Основа».
3. Карточка = **семейство** (один адрес). Не четыре карточки «с грибами / с пармезаном / в казане».
4. Поиск по названию и составу всегда на экране. Запрос даёт плоский список по всей книге с крошками вроде «Завтраки · духовка».

«Без молока» в книге можно как узкий отсев над уже выбранной главой, не как первый ряд. Кладовку «Есть» сюда не тащим.

### 5.3. Готовлю → карточка + режим готовки

Открыл `/recipes/classic-roast-chicken` (или пришёл из калькулятора с уже выбранной посудой). Дальше — §6 и §7.

### 5.4. Сверяюсь с таблицей → Справочник и Советы

Справочник — не рецепты. Это гиды, которые были в V1 и переехали в базу:

- **Крупы** `/grains` — таблица: крупа → пропорция воды, время, заметки.
- **Мясо** `/meat` → говядина / свинина / птица — карточки отруба: целевая температура, типичная ошибка.
- **Советы** `/tips` — приёмы Энди секциями (аккордеон).

Отдельных пустых сайтов «рыба», «море», «овощи» нет: пока нет таблицы — нет страницы. Рыба и море живут как глава книги и как живой чип калькулятора, когда в каталоге есть рецепты.

Внизу главной — ссылки Крупы · Говядина · Свинина · Птица · Советы Энди · Все рецепты.

## 6. Главная `/`

Не каталог и не копия калькулятора.

1. Короткий вход: что это за продукт. Две кнопки: **Подобрать блюдо** → калькулятор, **Все рецепты** → книга.
2. **Рецепты** — случайные шесть семейств **на каждую загрузку**. Без строки «почему подошло».
3. **Советы** — случайные шесть пунктов; карточка ведёт на нужную секцию `/tips`.

Пусто: «Рецепты пока не загружены» / «Пока нет советов». Не подменять книгой и не рисовать полный ряд фильтров.

## 7. Страница рецепта `/recipes/<slug>`

Одно **семейство** = один адрес. Добавки («с грибами») и посуда («в казане») — не новые блюда в книге, а переключатели на этой же странице. Клик сразу меняет состав, шаги, аллергены и заметки. Адрес помнит выбор, чтобы ссылка открывала тот же состав.

Порядок блока на экране:

1. Крошки: Рецепты / раздел / способ / название.
2. Название. Плашка «Готовил сам» — только если редакцию проверили готовкой человеком (агент её не ставит; сейчас почти ни у кого нет).
3. Словарные теги: основа, способ, тип блюда; посуда, если известна.
4. **Осторожно** — если блюдо high-risk (сырое, птица до температуры, фарш…). Без этого блока такое блюдо не публикуют.
5. Аллергены. Три состояния: содержит / может содержать / **неизвестно**. Неизвестное нельзя показать как «нет». «По желанию» (йогурт к карри) в аллергены блюда не входит.
6. Лид, источник (имя + ссылка, если чужой текст), блок **Заранее** (достать масло, разморозить…).
7. Два **отдельных** ряда, не один список чипов:
   - **Добавки:** Базовый · С грибами · С сыром… Нет добавок — ряда нет.
   - **Посуда:** Сковорода · Духовка · Казан… Нет второй посуды — ряда нет.
   «С грибами» и «в казане» не мешать в одну линейку.
8. Ингредиенты и жест **«У меня»** (см. ниже). Порции — только если в данных есть число порций. У «по вкусу» / щепотки справа иконка «эта строка не в КБЖУ» — только у жирного и сладкого (мёд, масло). Соль и перец — без иконки.
9. Если написаны калоражные версии — чипы **Обычный · Полегче · Сытнее** (редакционный состав, не «минус 20% ккал»). Ниже блок **«КБЖУ ориентировочно»**: на текущий масштаб; на 100 г продуктов **до** готовки; на 100 г готового — только если редакция задала выход; на порцию — только если есть порции. Неполный расчёт — заметная пометка, не мелкая серая. Дисклеймер: «Ориентировочно. Зависит от продукта и способа приготовления.» Это не диета и не медицинский блок рядом с «Осторожно».
10. Шаги текущих добавок и посуды. На шаге могут быть таймер и целевая температура внутри куска (°C). Время и температуры **не** растут вместе с порциями.
11. **Заметки** списком: заголовок + текст. Не одна простыня. Ноль заметок — секции нет.
12. **Режим готовки** и **Копировать ссылку**.

На гостевом срезе нет кнопок «В избранное» / «Я приготовил» / комментариев. Это следующий релиз; гость готовит и так.

### «У меня» — масштаб этого блюда

Только на карточке рецепта. Не на калькуляторе.

Якорь — первый масштабируемый ингредиент с граммами или миллилитрами (часто кусок мяса). Нет якоря (стейк «по вкусу» без граммов) — блока нет.

Жест: подпись «У меня»; минус / поле / плюс; г↔кг или мл↔л; коэффициент рядом, когда не 1; строка «имя якоря · в рецепте N»; сброс. Подсказка: **время готовки не пересчитывается** — таймеры подстраивают уже в режиме готовки.

Соль и специи масштабируются мягче, чем мясо (не ×5 при пяти порциях). Яйца и зубчики чеснока округляются до целых. Температуры и таймеры шагов не трогаем.

Первый HTML — базовые количества. Клиент пересчитывает сразу, без кнопки «Обновить» и без полной перезагрузки на каждый ввод.

## 8. Режим готовки

Полноэкранный оверлей. Вход — кнопка на рецепте (на телефоне ещё пункт таббара). Экран старается не гаснуть (Wake Lock). Показывает шаги **уже выбранных** добавок и посуды; внутри режима переключатели не дублируются, чтобы не сбить таймер.

**Сначала setup.** Когда начнёте: сейчас или запланировать. Если в рецепте есть «Заранее» — список напоминаний (масло за час, курица за полчаса). Сводка: сколько шагов, сколько с таймером. Кнопки: **Начать готовку**; при prep — **Только напоминания**.

**Потом шаги.** Крупный текст текущего шага; прогресс «шаг k из n»; таймер старт / пауза / сброс; ± длительности, пока таймер не бежит (шаг ± зависит от длины: 30 с / 1 мин / 5 мин); чекбокс «шаг выполнен»; Назад / Далее. Если на шаге есть температура — она видна.

На широком столе (≥769px) задуманы две колонки: слева текущий шаг и таймер, справа оглавление всех шагов (текущий выделен, клик = прыжок). На телефоне — один столбец, обзор «Все шаги» внизу.

Конец: «Готово!» и закрыть. Отчёт «я приготовил» — в следующем релизе, рядом с закрытием, не вместо него и не сам по себе при закрытии оверлея.

## 9. Как устроен рецепт внутри (без жаргона разработки)

Карточка на сайте собирается из одного JSON-семейства. Человеку это не видно, аналитику полезно понимать границы продукта.

**База** — обычный состав и шаги (то, что на чипе «Базовый» / дефолтная посуда).

**Вариант** — редакционная версия того же блюда. Две оси:

- добавки: положили перец и помидор в омлет;
- посуда: тот же омлет в духовке, другие шаги и чуть другой жир.

Вариант хранится как **дельта**: что добавить / заменить / какие шаги переписать. Не копия всего рецепта и не вторая карточка в оглавлении. Осей 0–10, только если альтернатива реально полезна. Квоты «обязательно три варианта» нет.

**Адаптация** — заранее разрешённая операция подбора («сливки можно заменить молоком», «это можно в духовке»). Калькулятор **не** выдумывает «наверное получится в казане», если этого нет в данных.

**Канон ингредиента** — общий справочник продуктов (`яйца`, `сливочное масло`). Аллерген висит на каноне, не на подстроке «молоко» в тексте. Поэтому «миндальное молоко» не помечается коровьим молоком, а соевый соус — соей.

Поля, которые человек видит косвенно: время всего / у плиты, сложность 1–5, сколько мыть посуду, в каких ситуациях блюдо хорошо (быстро, просто, из кладовки…). Это топливо калькулятора, не обязательные бейджи на карточке.

## 10. Пример семейства с двумя осями — омлет

Адрес: `/recipes/omlet`. В книге — глава **Завтраки**.

На карточке два ряда:

| Добавки | Посуда |
|---------|--------|
| Базовый | Сковорода (по умолчанию) |
| С овощами | В духовке |
| С сыром | |

База: 4 яйца на 2 порции, молоко **или** вода (один выбор), масло, соль, перец, укроп. Жарят на сковороде под крышкой, центр не оставляют сырым.

«С овощами» добавляет перец и помидор и вставляет шаг «сначала выпарить жидкость». «С сыром» сыплет твёрдый сыр, когда края схватились. «В духовке» меняет посуду на форму, температуру 180 °C и таймер запекания; сковороду не разогревают.

Это всё ещё **один** омлет в оглавлении. Калькулятор, подобрав «яйца + быстро», может сразу открыть `?equipment=oven` или базовую сковороду.

## 11. Пример одного полного рецепта — классическая запечённая курица

Так человек видит карточку `/recipes/classic-roast-chicken`. Ниже схема объекта: в массивах по **одному** элементу, не полная карточка. Живой рецепт — в Postgres.

**Крошки.** Рецепты → Птица → духовка → Классическая запечённая курица.

**Название.** Классическая запечённая курица.

**Теги.** Птица · духовка · основное · посуда: духовка. Часть: целая тушка.

**Осторожно.** Целая птица: проверить термометром грудку (не ниже 72 °C) и бедро (не ниже 82 °C). Не ориентироваться только на цвет сока. Не для детских подборок без дополнительной проверки.

**Аллергены.** Молоко — содержит (сливочное масло). Остальное по канонам состава.

**Лид.** Цыплёнок с чесночно-тимьяновым маслом под кожей, 200 °C, отдых 15 минут.

**Источник.** Andy Cooks, статья с сайта автора.

**Заранее.**

- За 60 мин: достать сливочное масло — должно быть мягким.
- За 30 мин: достать курицу, обсушить кожу.

**Посуда.** База — духовка. Второй чип — **На гриле** (непрямой жар, поворот тушки). Это тот же slug, другие шаги 1, 7 и 8.

**Состав (база, 4 порции).**

| Что | Сколько |
|-----|---------|
| Курица, целая | 1 шт. |
| Сливочное масло, несолёное, комнатной температуры | 150 г |
| Лимон | 1 шт. |
| Чеснок | 3 зубчика |
| Соль | по вкусу |
| Перец, свежемолотый | по вкусу |
| Тимьян, небольшой пучок | 1 пучок |

«У меня» появится, если в сборке есть весовой якорь; у этой карточки якоря в граммах на тушке нет — блок может отсутствовать, порции при этом есть.

**КБЖУ.** Ориентировочно по канонам продуктов на входной набор (масло входит целиком). На 100 г готового — только если редакция задала выход; здесь выхода нет, ячейки готового нет. Соль и перец «по вкусу» в сумму не входят.

**Шаги (духовка).**

1. Разогреть духовку до 200 °C с конвекцией или 210 °C без неё.
2. Смешать мягкое масло с цедрой лимона, тёртым чесноком, солью, перцем и тимьяном.
3. По желанию удалить дужку из грудки.
4. Лимон пополам внутрь тушки, посолить полость; смазать низ солью и маслом.
5. Отделить кожу от грудки и распределить масляную смесь под кожей.
6. Обвязать шпагатом, обмазать оставшимся маслом снаружи, посолить.
7. Запекать; после 40 минут проверять температуру. Мелкая птица 45–50 мин, крупная до 1 ч 10 мин, до **82 °C** в самой толстой части бедра. Таймер ~50 мин — ориентир, снимать по щупу.
8. Отдохнуть 15 минут. Грудку проверить: не ниже **72 °C**.

На гриле шаг 1 — две зоны жара; шаги запекания заменяются на непрямой жар с поворотом; аэрогриль эта тушка не обещает.

**Заметки (список).**

- Масло должно быть мягким, иначе под кожей не распределится.
- Кожу перед запеканием обсушить — иначе не будет хрустящей корочки.
- Щуп в самую толстую часть бедра, не касаясь кости. Цвет сока — не критерий.
- Отдых 15 минут фиксированный, от размера тушки не зависит.
- Под курицу можно выложить картофель, морковь и лук; корнеплоды — спустя ~20 минут, чтобы не разварились.
- Соус из соков: эшалот, бульон, масло, хересный уксус. Количеств нет — это не отдельный вариант. Магазинный бульон часто с сельдереем.
- К рецепту Andy Cooks есть видео.
- На гриле только непрямой жар; масло под кожей не поливать на угли. Казан эту тушку не обещает: кожа преет.

**Режим готовки** подхватит prep (масло, обсушить), два таймера (запекание и отдых) и температуры на шагах 7–8.

## 12. Что уже в гостевом срезе и что нет

**Уже можно без входа:** витрина, калькулятор, книга с оглавлением, карточка семейства, «У меня», режим готовки, крупы / мясо / советы, поиск, аллергены и «Осторожно», ориентировочное КБЖУ, редирект со старого URL.

Каталог: все 43 рецепта старого сайта плюс новые волны (десятки блюд сверх V1: завтраки, овощи, море, десерты…). Точное число смотреть на живом `/recipes`. Часть семейств уже с добавками и второй посудой; у многих по-прежнему одна ось — переключатель тогда скрыт, это честно.

**Следующий релиз (аккаунты, не в этом срезе):** вход по российской почте (не Gmail), избранное, «я приготовил», кладовка как набор чипов без граммов, оценка и комментарий «Участник · дата». Гость по-прежнему полный продукт; вход нужен, чтобы **сохранить** или **написать**. Первый публичный переезд на домен — всё ещё без аккаунтов.

**Позже:** граммы и срок в кладовке, список покупок с количествами, фото к отчёту «приготовил», печать, постоянное имя вместо «Калькулятор».

**Не планируется, пока явно не попросили:** runtime-ИИ на сайте, пользовательская публикация рецептов, оплата, приложение в сторах, логин через Госуслуги/телефон.

В приложении **нет** языковой модели. Рецепты пишутся отдельно, проходят проверку схемы и модерацию, затем импортируются в базу.
