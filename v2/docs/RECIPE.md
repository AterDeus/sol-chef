# Рецепты агентами — sol-chef 2.0

Контракт черновиков. Словари: [VOCAB.md](VOCAB.md). Безопасность: [SAFETY.md](SAFETY.md). Задача сессии: [../CURRENT_SPRINT.md](../CURRENT_SPRINT.md).

В приложении LLM нет. Черновики — файлы → `import_draft` в Postgres. Корневой `data/recipes/` не переписывать.

Два потока, один формат JSON:

| Поток | Когда | Сколько |
|-------|--------|---------|
| **Оверлей 43** | человек сказал переделывать существующие в БД | по одному slug; единообразный объект для поиска, масштаба и **безопасной** адаптации |
| **Волна новых** | явный старт в чате / CURRENT_SPRINT («стартуй волну N») | packet из [drafts/packets/](drafts/packets/README.md); волны **1–9 уже в БД** (85 slug) |

Эталон структуры: `v2/backend/tests/fixtures/gold_overlay.json` плюс профиль (`time_profile`, effort/washing, `use_cases`) и `adaptations[]`. Квота «ровно 3 варианта» **запрещена**. Варианты 0–10, только полезная альтернатива. Живой каталог — Postgres; выгрузка: `export_draft --slug`.

Полный §4A брифа (роли `required`/`substitutable` на каждой строке) **ещё не** в этом JSON. В каноне уже: профиль, `use_cases`, `adaptations`, реестр `Ingredient`.

## Конвейер

**По умолчанию:** Grok 4.6 High (автор) → GPT-5.6 Terra Medium (модератор). Схема/VOCAB/SAFETY — скрипт, не модератор.

Гибрид: editorial-рецепт можно отдать Terra как автору только если стоимость принятого ниже ≥15% при среднем ≥4.5 и 0 Critical. `source_backed` всегда Grok→Terra.

| Роль | Кто | Делает |
|------|-----|--------|
| Автор | Grok 4.6 High | один JSON-рецепт по packet |
| Валидатор | скрипт, не модель | schema, VOCAB, SAFETY, дубли |
| Модератор | Terra Medium | `cookable` + `real` + короткий вердикт; **не** полный JSON при revise |
| Нормализация | Composer Fast | только формальные ошибки валидатора, без смены состава |
| High-risk | человек | допуск + текст блока «Осторожно» |
| `editorial_tested` | человек (trusted) | агент **не** ставит |

## Когда писать

**Оверлей.** Packet = текущий V1 JSON этого slug (файл в `data/recipes/`) + taxonomy + SAFETY. Не выдумывать другой бриф. Цель: тот же блюдо, тот же `id`, **структурированный объект** (поиск, якорь, SAFETY, профиль, только осмысленные дельты и адаптации). Не «переписать JSON ради JSON».

**Волна новых.** Есть input packet из [drafts/packets/](drafts/packets/README.md). Без packet — `{ "error": "…" }`. Человек явно стартовал пачку в чате / CURRENT_SPRINT. Волны 1–9 (**85** slug) уже написаны. Следующая пачка — только после нового старта. Оси посуды на существующих slug — **«стартуй оверлей осей N»**, не новая волна.

Стоп: ≥1 Critical после модерации; revise > 40%; schema first-pass < 80%; средний балл < 4.0; выдуманный URL/таймкод; скрытый аллерген; независимый агент `cookable: false`.

## Коды — только VOCAB

Не писать `duhovka`, `skovoroda`, `kastryulya`, `tushenie`. Не ставить жарку в `dish_type`.

- `cook_method`: `oven` / `pan_fry` / `stew` / `boil` / `grill` / `steam` / `no_cook` (+ черновик `air_fryer` `deep_fry`)
- `dish_type`: роль на столе (`main`, `soup`, `salad`…). Масла, бастинг, жареный лук как заготовка — `sauce` / `preserve`, не `breakfast` и не ответ калькулятора «что приготовить»
- `protein_base`: включая `seafood`, `offal`, `eggs_dairy`, `vegetables`, `mushrooms`, `legumes`, `fruits`; омлет ≠ овощи; желе/кисель ≠ овощи
- `energy_profile`: `standard` / `light` / `rich` — дельты того же рецепта, не второй id, не ккал
- единицы: `g` `kg` `ml` `l` `pcs` `tsp` `tbsp` `pinch` `clove` `bunch` `slice` `to_taste`. Стакан запрещён. Ложка в JSON — `tbsp`/`tsp`; мл в скобках рисует карточка (`1,5 ст. л. (~23 мл)`). В `detail` не писать «около 23 мл».
- `id`: транслит русского `title`, не английский перевод.
- Заготовка (томлёная говядина на волокна и т.п.) — отдельный канон из `PANTRY_PREP` (`shredded_beef`), не сырой `beef` / отруб. Чип вида в калькуляторе = сырое мясо. Заготовки — вкладка **Полуфабрикаты** под мясом. На карточке появляется пометка «Нужна заготовка».

Маппинг V1 → V2 — таблица в VOCAB. Папки `data/recipes/duhovka/` не переименовывать.

## Шкаф (не база блюда)

База — то, ради чего идут в магазин: мясо, овощи, крупа, банка, сыр, зелень пучком, хлеб к тарелке. Шкаф — то, что дома и так есть. Добавить из списка можно без смены «ингредиентной базы»: packet, закупка набора и ядро «докупить» не раздуваются.

**Когда можно.** Блюду лучше (вкус, баланс, физика): щепотка сахара к томатам, капля лимона к томлёному мясу, ложка муки в соус, крахмал в болтушку. Нельзя прятать в шкаф якорь и основную массу: 400 г муки на блины, стакан сахара на компот, бутылка масла как заготовка — это база.

**На карточке.** Если из списка ниже в составе есть хотя бы одна строка — над списком базы, до «У меня», блок:

**Из шкафа:** соль, сахар, лимонный сок.

Только названия, через запятую, в бытовом русском. «A или B» из шкафа — через «или»: *лимонный сок или уксус*. Пустой блок не рисовать. В основном списке эти строки не дублировать как закупку. Приложение собирает блок само по канону и единице; автор не пишет отдельное поле.

**В JSON.** Строка ингредиента обязательна: `canonical_id` из таблицы, количество, `scale_mode` (`gentle` у приправ). Каждый такой продукт — в конкретном шаге. `new_ingredients` на канон из таблицы не заводить, если он уже в сиде.

**Не в закупку набора.** `PANTRY_ASSUMED` и этот список. Калькулятор уже не докупает щепотку / ч. л. специй и assumed; лимон в ложке — шкаф, не «нужно докупить лимон».

Закрытый список (экран → `canonical_id`). Нет в таблице — это база, даже «маленькая пачка».

| На карточке | Канон | Когда ещё база |
|-------------|--------|----------------|
| вода | `water` | никогда: вода из-под крана |
| соль | `salt`, `coarse_salt` | никогда |
| сахар | `sugar` | ≥50 г: сироп, компот, выпечка |
| чёрный перец | `black_pepper` | никогда |
| растительное масло | `vegetable_oil` | ≥100 мл как заготовка / заливка |
| лимон / лимонный сок | `lemon` | никогда в этом списке (сок к блюду, не лимонад литрами) |
| уксус столовый или яблочный | `vinegar`, `vinegar_9` | бальзамик и винный — база, не этот канон |
| мука пшеничная | `wheat_flour` | ≥50 г: тесто, панировка горкой, блины |
| крахмал | `corn_starch` | ≥50 г |

Оливковое к подаче, зира, паприка, чеснок, томатная паста — **не** шкаф: их нет в таблице.

## Автор

Вернуть **только** JSON рецепта (или `{ "error": "чего не хватает" }`).

- Факты только из packet. Не выдумывать URL, таймкоды, бренды, редкие продукты.
- Ингредиенты: объекты; «A или B» — два с одним `choice_group`. Это взаимоисключающая **закупка**: в корзине одна ветка. `new_ingredients` регистрирует каноны всех веток, которые *могут* встретиться в рецепте (фета и брынза, горбуша и тунец). Это заявка в реестр, не список «купить всё сразу».
- **Шкаф, не база** — закрытый список в § «Шкаф». Приправу и техническую мелочь из него можно добавить, если блюду так вкуснее или стабильнее (сахар к томатам, лимон к желе). Это **не** меняет базу блюда: не новый slug, не строка закупки набора, не ядро калькулятора «докупить». В JSON строка всё равно нужна (количество, `gentle`, шаг). На карточке — блок **Из шкафа:** над составом. Расширяет список только человек в RECIPE.md.
- Шаги — объекты `{ "text": "…" }`, единый стиль (инфинитив **или** повелительное). На карточке — русский для человека: без id, кодов VOCAB, «якорь», «Первый проход», калек (`наппировать`, «жест», «другой рот»). Не объяснять блюдо через соседний рецепт («это не лодочки», «сыр не нужен», «другой id»), если это не шаг готовки. Писать, что делать с тем, что есть в составе. Вариант: каждый новый ингредиент в конкретном шаге; влажная замена сахара — отдельная рецептура, не подстановка.
- Птица/рыба: `target_internal_temperature_c` (валидатор смотрит target, не pull). Бедро **на кости** — 82 °C; филе бедра без кости (полоски) — 74 °C, не «у кости». Не писать, что кремовое яйцо или жидкий желток безопасны «потому что края схватились».
- Аллергены честно: неизвестное → `unknown` **на каноне** (`new_ingredients` или уже реестр). На строке рецепта `allergens_*` не писать.
- Соль/специи: `gentle`. Сода в бархате/маринаде (пропорция к мясу) — `linear`. Сода/дрожжи/желатин в выпечке — `manual`. Не `gentle` (это автодетект V1).
- `pan_fry`: в шаге жарки — не перегружать сковороду.
- **Отрубы / части** (`allowed_cuts` в JSON: **коды** из [VOCAB.md](VOCAB.md) `cut`; в UI — `title_ru` как в РФ). Автор обязан перечислить, какие части **можно** — и в новой волне, и при переработке существующего. Говядина: голяшка, лопатка, шея, рёбра, вырезка, толстый край — не ribeye в подписи. Птица: бедро, голень, грудка, крыло, целиком. Рыба/овощи в этот словарь в спринте 2 не входят (`[]`). Не про мясо — список пустой, фильтр не врёт.
- **Профиль (уровень B, оверлей обязателен):** `time_profile.total_minutes` / `active_minutes`, `effort_level` 1–5, `washing_level` 1–5, `use_cases` из VOCAB (можно `[]`). Таймеры шагов это не заменяют.
- **Восемь вопросов** перед JSON: 1) основа (`protein_base`); 2) чем готовить; 3) что обязательно; 4) что можно убрать (`omission`); 5) что заменить (`substitution`); 6) другой способ (`equipment`/`method` adaptation); 7) хорошие редакционные варианты; 8) в каких ситуациях хорош (`use_cases`). Не выдумывать замены и смену посуды.
- **Вариации** (`variants`, уровень C): редакционная версия блюда, не адаптация калькулятора. Дельты состава и шагов того же `id`. **0–10**. Обязательны только если создают полезную альтернативу. Не заполнять ради квоты. Бульон без addon — норма. Не плодить карточку в каталоге. Если чип меняет основу блюда (замена якоря / «без мяса» / мясо в овощную карточку) — обязателен `protein_base_override` из VOCAB, не равный базе. Тогда в `title` не писать один белок («Домашняя шаурма», не «…из курицы»); slug уже выданный не трогать. Гарнир и формат (боул, острота, бекон поверх) поле не ставят. Две основы в одной кастрюле без чипа — `protein_bases_extra` на корне, не override. Если вариант меняет нарезку или подготовку строки базы — `ingredient_delta.replace` с новым `detail`. Список продуктов читают раньше шагов; общая заметка в конце карточки это не чинит. `notes` общие для всех чипов: в них нельзя писать «круги базы не годятся» / технику только одного чипа, которая противоречит базе. Нюанс чипа — в дельте шага и строки.
- **Адаптации** (`adaptations`, уровень C): разрешённые операции движка (`substitution` / `omission` / `equipment` / `method`). Можно `[]`. Runtime не додумывает «можно в духовке».
- `new_ingredients` — только заявка на отсутствующий канон. После регистрации в сиде блок из утверждённого файла убрать.
- `prep`: либо пункты с `text` (достать мясо, разморозить), либо ключа нет. Пустой `[]` запрещён.
- Текстовый формат V1 `variations[].text` для **новых** рецептов **запрещён**, если меняется состав: только дельта ингредиентов и шагов + `allergen_delta` (SAFETY). Иначе — не вариация.
- **Посуда** (кастрюля / духовка / казан у одного блюда): ось варианта **или** `adaptations` type=equipment, не второй рецепт. Нюансы времени, крышки, жидкости — в дельте. Не сваливать «а в казане иначе» в один абзац `notes`. Не путать с `cook_method` (жарка vs тушение).
- **Заметки** (`notes` / chef notes): список `{ "title", "text" }`, не blob и не `chef_tip`. Не дублировать шаги дословно. Класть: подготовка мяса/рыбы, обжарка да/нет, бульон vs вода, специи «можно», посуда только если это не ось варианта, типичные ошибки. Не писать «это не соседнее блюдо» и не перечислять продукты, которых нет в составе («сыр не нужен»). Заголовок «Не лодочки» / «Не борщ» запрещён.
- Квоты заметок для **новых** рецептов волн: min **3**, цель **6**, max **10**. Не лить воду ради числа (лучше 3 сильных, чем 10 пустых). Сложное блюдо (тушение, оссобуко, плов) — целиться в 6–10.
- **Когда квоты и тексты заметок:** с первой волны после явного старта и **в момент** написания или переработки конкретного рецепта. Не отдельным проходом по 43. ETL V1 **не** добирает заметки до 3.
- Если packet просит калораж: `light` и/или `rich` как дельты состава и шагов + `allergen_delta`. Не считать ккал вручную. `energy_profile` — не ккал. Не подменять блюдо. Не решать через `energy_profile` быстро / просто / мало посуды.
- Ключи `kcal` / `nutrition` / `protein_g` / `per_100g_cooked` / `per_100g_input` на **корне** рецепта запрещены (валидатор). КБЖУ считает приложение с канона `Ingredient` (DEC-022, DEC-023).
- На строке ингредиента можно `nutrition_exclude: true` (целиком вне числителя и массы). Нет ключа = `false`. Частичный вклад — `nutrition_factor` 0.01–1 (нет ключа = 1). Ноль запрещён. Не вместе с exclude.
- `yield_weight_g` — граммы готового на базе, только если редакция знает выход. `yield_kind`: `estimated` (дефолт) \| `exact`. Не выдумывать на оверлее 43.
- `to_taste` / `pinch` можно и на масле, мёде, майонезе и прочих жирных канонах (DEC-024). Строка не входит в КБЖУ и не ставит `incomplete`. На карточке — иконка с тултипом у жирного/сладкого; соль и специи не показываем. Граммы ставить, когда в источнике есть число; «по вкусу» вместо граммов у мяса/рыбы/крупы/основного овоща по-прежнему нельзя.
- `servings`: на **новых волнах** ставить, если в источнике/packet есть число. Оверлей 43 — не выдумывать `4`.
- `editorial_tested` / `community_confirmed` / V1 `tried` не заполнять.
- Чужой текст: имя источника + `source_url`. Editorial без URL — норма. Без атрибуции чужого — Critical. Рецепт должен быть воспроизводимым, не галлюцинацией.

Пример заметки (не полный рецепт):

```json
"notes": [
  { "title": "Подготовка мяса", "text": "Голяшку надрезать у кости, иначе жила стянет кусок." },
  { "title": "Бульон или вода", "text": "Вода допустима; бульон гуще. Магазинный кубик — смотрите состав (сельдерей)." },
  { "title": "Ошибка", "text": "Не заливать мясо холодной жидкостью сразу после обжарки — корочка размокнет." }
]
```

## Модератор (независимый агент)

Модель: **GPT-5.6 Terra Medium** (`gpt-5.6-terra-medium`). Не автор. Лимит токенов: Terra **не читает репозиторий**.

Оркестратор сам читает черновик и **вставляет в промпт чеклист + JSON рецепта**. Промпт: [drafts/reviews/PROMPT.md](drafts/reviews/PROMPT.md). Запуск Task: `model=gpt-5.6-terra-medium`, без `file_attachments`. В задании **явно**: не вызывать инструменты, не открывать файлы репозитория, не Grep/Glob/Read/Shell.

Terra **не** получает пути и **не** открывает: `RECIPE.md`, `VOCAB.md`, `SAFETY.md`, packet V1, отчёт валидатора, другие рецепты. Схему уже проверил скрипт. Terra проверяет по чеклисту в промпте: можно приготовить, ничего не упущено, будет вкусно, техника реальна, продукты из магазина РФ; вариант не теряет ингредиент в шагах и не ломает физику блюда механической заменой; на карточке нет внутреннего жаргона и калек.

Вердикт Terra — в чат (файл в `drafts/reviews/` не нужен для импорта). Объект:

- `verdict`: `accept` \| `revise` \| `reject`
- `cookable` — `true` только если домашний повар может приготовить **это** блюдо по шагам и количествам, без «догадайтесь сами»
- `real` — техника существует, не галлюцинация. `source_url` в **черновике** (не в V1 packet): пустой/`null` у editorial — норма; выдуманный URL — `real: false`
- `comment` — 2–5 предложений, почему
- `recipe_json` — всегда `null` (правки пишет автор, не Terra)
- `critical` / `major` / `minor` — короткие строки; можно `[]`

Без `cookable: true` в каталог нельзя. `revise` = в `comment` что исправить; полный объект рецепта Terra не пишет. `sol-chef.ru` в корневом V1 JSON — не основание reject, если в черновике 2.0 URL уже нет.

## High-risk

Флаги и температуры — SAFETY. В каталог можно после человека. На странице обязателен блок «Осторожно». Не в детские и «диетически безопасные» подборки.

## Качество (ворота)

| Уровень | Пример |
|---------|--------|
| Critical | температура птицы ниже минимума; `unknown` объявлен «нет»; выдуманный URL; чужой текст без ссылки |
| Major | нет количеств у primary; «по вкусу» вместо граммов у мяса/рыбы/крупы/основного овоща; сломанная диета; пропущен ключевой шаг; `variations[].text` вместо дельты; второй slug вместо дельты; посуда только в notes; варианты ради квоты; `allergens_*` на строке рецепта; пустой `prep: []`; `kcal`/`nutrition`/`protein_g`/`per_100g_*` на корне рецепта; `nutrition_factor` 0 или вместе с exclude; вариант меняет нарезку, а `detail` базовой строки не заменён; шкаф использован в шагах, а строки нет в составе; на карточке шкаф есть, блока **Из шкафа** нет |
| Minor | стиль, лишний тег; пустые заметки ради квоты; notes копируют шаг дословно; объяснение блюда через «это не соседний рецепт» / «X не нужен»; англицизмы и кальки в шагах (`наппировать`, «жест», «другой рот») |

Неисправленный Critical = fail. Средняя человеческая оценка (воспроизводимость, пропорции, шаги, ограничения, вариации-дельты, заметки, русский, evidence) ≥ 4.0.

Квоты 3 / 6 / 10 — ворота **новых** волн **и оверлея 43 в момент переработки**. ETL V1 заметки до 3 не добивает. Минимумы температур — только [SAFETY.md](SAFETY.md), здесь не смягчать.

## Куда класть черновики

- Правка существующего: `python manage.py export_draft --slug <id> --path v2/docs/drafts/recipes/<id>.json`
- Новый slug: `v2/docs/drafts/recipes/<slug>.json`
- В Postgres: `python manage.py import_draft --path …` (вердикт Terra не gate). Не в корневой `data/`.

Локальный Compose **не** гоняет `import_v1`: каталог — том Postgres. Карточки с `time_profile` **не** откатываются к V1. Том Postgres — источник правды оверлея и волн. ETL V1 — ручная команда / pytest, не старт среза.
